# HTTP

## 定义

全称为HyperText Transfer Protocol，译作超文本传输协议。它是计算机网络中**两点**之间传输文字、图片、音频等**超文本**数据的**规范**。更详细地说，

+ HTTP是一个**双向传输**协议；
+ HTTP虽然在两点传输，但允许中转，中间者可以增加信息（比如传输的HTML文本中图片可能是指向第三方的链接），也必须遵循HTTP协议；
+ HTTP约定了通信的格式，此外还有各种控制和错误处理的方式；



## 状态码

| 状态码 | 含义                                                         |
| ------ | ------------------------------------------------------------ |
| 1xx    | 提示信息，协议处理的中间状态，较少用到。                     |
| 2xx    | 成功，服务器成功处理了客户端请求。                           |
| 3xx    | 重定向，请求的资源位置发生了变动，需要客户端用新的URL重新请求。 |
| 4xx    | 客户端错误，请求报文有误，服务器无法处理。                   |
| 5xx    | 服务器错误，客户端发送的报文正确，服务器在处理请求时发生了错误。 |

| 2xx状态码 | 含义                                                         |
| --------- | ------------------------------------------------------------ |
| 200       | OK，响应头包含body数据。                                     |
| 204       | No Content，响应头没有body数据。                             |
| 206       | Partial Content，响应返回数据只是资源的一部分，在 HTTP 分块下载或断点续传中较常见。 |

| 3xx状态码 | 含义                                                         |
| --------- | ------------------------------------------------------------ |
| 301       | Moved Permanently，永久重定向，请求的资源已经不在了。响应头字段Location指定了要跳转的URL。 |
| 302       | Found，临时重定向，请求的资源还在,但暂时需要用另一个URL来访问。响应头字段Location指定了要跳转的URL。 |
| 304       | Not Modified，缓存重定向。                                   |

| 4xx状态码 | 含义                                                  |
| --------- | ----------------------------------------------------- |
| 400       | Bad Request，客户端通用错误。                         |
| 403       | Forbidden，报文本身正确，只是服务器器禁止止访问资源。 |
| 404       | Not Found，请求的资源不存在。                         |

| 5xx状态码 | 含义                                                         |
| --------- | ------------------------------------------------------------ |
| 500       | Internal Server Error，服务器通用错误。                      |
| 501       | Not Implemented，请求的业务还不支持。                        |
| 502       | Bad Gateway，通常是服务器作为网关或代理时返回的错误码，表示服务器自身工作正常,访问后端服务器发生了错误。 |
| 503       | Service Unavailable，服务器繁忙，暂时不能响应。              |



## 字段

| 字段             | 作用                                                         |
| ---------------- | ------------------------------------------------------------ |
| Host             | 服务器的域名，如www.kensporger.com。使用不同字段可以将请求发往同一台（多台）服务器上的不同网站。 |
| Content-Length   | 服务器本次回应的数据长度。                                   |
| Content-Type     | 服务器本次回应的数据格式。例如Content-Type: text/html，表明发送的是网页。 |
| Accept           | 客户端请求时，声明自己可以接受的数据格式。例如Accept: \*/\*，表示可以接受任何格式。 |
| Content-Encoding | 服务器本次回应的数据使用的压缩格式，客户端应该使用相同格式解压。例如Content-Encoding: gzip。 |
| Accept-Encoding  | 客户端请求时，申明自己可以接受的压缩格式。                   |



## GET和POST

GET用于请求资源，例如打开博客文章；POST则是向服务器提交数据，数据放在报文的body里，例如评论区留言。GET方法是安全和幂等的，POST方法是不安全和非幂等的。

> **安全**：请求方法不会修改服务器上的资源。
>
> **幂等**：多次执行同样的请求，结果都是相同的。



## 特点

### 无状态

HTTP是无状态的。无状态的好处在于服务器不用去记录状态信息，这能减轻服务器的负担。坏处在于完成一系列关联性操作时非常麻烦，例如登录->添加购物⻋车->下单->结算->支付，这系列操作服务器不知道这些请求是有关联的，所以每次都要问一遍身份信息。

解决无状态问题比较常用的方法是Cookie技术。Cookie通过在请求和响应报文中写入Cookie信息来维持客户端的状态。具体来说，在客户端第一次请求后，服务器会下发一个记录客户状态的Cookie信息，之后客户端再次请求时，带上该Cookie信息，以便服务器回忆起客户的状态。事实上，Cookie技术将状态的存储任务交给了客户端自己去负责。当我们在浏览器中主动清理Cookie后再访问某个网站，就需要重新身份验证。

### 不安全

HTTP是明文传输协议。明文意味着在传输过程中的信息都是可方便阅读的，通过浏览器的F12控制台和Wireshark抓包都可以直接肉眼查看，方便调试。另一方面，明文也使得信息毫无隐私可言。

+ 窃听风险：明文传输；
+ 篡改风险：无法验证报文的完整性，所以有可能已遭篡改。比如网页上被植入垃圾广告。
+ 冒充风险：不验证通信方身份，可能遭遇伪装。比如访问假的淘宝。



### 长连接

HTTP协议是基于TCP/IP，并且使用了请求-应答的通信模式。早期的HTTP版本，每发起一次请求都要新建一次TCP连接。之后HTTP采用了长连接的通信方式，也叫作持久连接。这种方式减少了TCP连接的重复建立和断开所造成的额外开销。持久连接的特点是：只要任意一端没有明确提出断开连接，则保持TCP连接状态。

### 管道网络传输

管道机制是允许客户端发出一次请求后，不需要等到回应就可以发送第二次请求。但是服务器还是一个个处理请求的，处理第一个请求时，其他请求必须排队等候，于是造成了**队头阻塞**问题。



# HTTPS

HTTPS在TCP和HTTP网络层之间加入SSL/TLS安全协议，解决了HTTP不安全的三大问题：

+ 提供信息加密：使用混合加密算法，传输的信息无法被窃听；
+ 提供校验机制：使用摘要算法，可以验证报文的完整性，当不完整时不给予显示；
+ 提供身份证书：将服务器公钥放入到数字证书中，解决冒充的风险；



## 混合加密

HTTPS采用了对称加密和非对称加密的混合方式：

+ 在通信建立前采用非对称加密的方式交换会话秘钥（客户端向服务器索要公钥，然后用公钥加密信息，服务器收到密文后，用自己的私钥解密），后续就不再使用非对称加密；
+ 在通信过程中全部使用对称加密的会话秘钥的方式加密明文数据。

> **非对称加密**：使用两个密钥：公钥和私钥，公钥可以任意分发而私钥保密，解决了密钥交换的安全问题但是速度慢。
>
> **对称加密**：只是用一个密钥，运算速度快，但是无法做到安全的密钥交换，所以密钥必须被保密。



## 摘要算法

摘要算法为数据生成独一无二的指纹。客户端在发送明文之前会通过摘要算法算出明文的指纹，发送时把指纹和明文一同加密成密文后发给服务器，服务器解密后，用相同摘要算法算出明文的指纹，通过比较两次指纹验证数据的完整性。



## 数字证书

在服务器向客户端发送公钥时，公钥可能被篡改，这就需要数字证书认证机构将服务器公钥放在数字证书中，只要证书可信，公钥就可信。

## SSL/TLS协议流程

+ 客户端向服务器索要并验证服务器的公钥；
+ 双方协商产生会话密钥；
+ 双方采用会话密钥进行加密通信；





# IP基础



## IP和MAC

IP属于网络层，MAC属于数据链路层。MAC的作用是实现直连的两个设备之间的通信，而IP负责在没有直连的两个网络之间进行通信传输。在传输过程中，源IP地址和目标IP地址不发生变化，但是源MAC地址和目标MAC地址会发生变化。



## IP地址分类

IP地址分为五类：A类、B类、C类、D类和E类。

| 类别 | 类别标识 | 网络号 | 主机号 | 地址范围                  | 最大主机数 |
| ---- | -------- | ------ | ------ | ------------------------- | ---------- |
| A类  | 0        | 7位    | 24位   | 0.0.0.0~127.255.255.255   | 16777214   |
| B类  | 10       | 14位   | 16位   | 128.0.0.0~191.255.255.255 | 65534      |
| C类  | 110      | 21位   | 8位    | 192.0.0.0~223.255.255.255 | 254        |

最大主机数=2^主机号位数-2。减去的这两个主机地址为全0和全1：

+ 主机号全为1代表某个网络下的所有主机，用于广播，例如192.168.0.255。
+ 主机号全为0代表某个网络本身；

D类和E类地址没有主机号，所以不可以用于主机IP，D类多被用于组播，E类地址为预留地址，未使用。



## IP地址的缺点

+ 同一网络下没有地址层次。如公司采用了B类地址，但是可能需要根据不同生产环境划分地址层次，但是IP地址无法做到；
+ 无法与现实网络匹配。C类地址的主机数过少，而B类的主机数又过多。
