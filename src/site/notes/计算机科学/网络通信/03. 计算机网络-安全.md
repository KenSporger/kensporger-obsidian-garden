# 网络安全定义

网络安全是指网络系统的硬件、软件及其系统中的**数据受到保护**，不因偶然的或者恶意的原因而遭受到**破坏、更改、泄露，系统连续可靠正常地运行，网络服务不中断**。



# 如何保证网络安全

网络中的非法分子常见的行为有：**窃听、冒充、篡改、劫持、拒绝服务DoS**。

> **劫持**：通过移除/取代发送发或者接收方“接管”连接，导致原通信双方无法建立正常连接。
>
> **拒绝服务DoS**：通过过载资源等方式阻止服务器为其他用户提供服务。

因此为了网络的安全至少需要保证以下方面：

+ **报文机密性**：只有通信双方可以将加密的报文解出，防止第三方**窃听**。
+ **身份认证**：双方能够确认彼此的真实身份，防止第三方**冒充**。
+ **报文完整性**：接收方能够判断接收到的报文和发送者发送的内容是否一致，防止第三方**篡改**。
+ **可访问与可用性**：网络服务必须对被授权用户可访问与可用，避免受到**劫持**和**拒绝服务**攻击。



# 网络攻击和预防



## 基本攻击手段

在Internet中常见的基本攻击手段有：**扫描**、**嗅探**、**IP欺骗**、**拒绝服务DoS**等。

+ **扫描**：扫描手段通常用于发起攻击之前，目的是找出网络上正在运行的各种服务。在扫描手段中常会使用ping命令先确定网络中可访问主机的地址，然后进行**端口扫描**，即依次尝试与该主机上的每个端口建立TCP连接，以此判断该主机上运行的服务。

+ **嗅探**：使用的嗅探前提是，主机接入**广播介质**（共享式以太网、无线网络等）中，通过将主机的网络接口设置为**混杂模式**来接收所有经过的分组（非混杂模式下，只会接收目的IP和自己匹配的分组），然后就可以读到所有未加密的数据。

  ![92a2472e920f9f1365285d52d1bb9825_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E7%BD%91%E7%BB%9C%E9%80%9A%E4%BF%A1/assets/03.%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%BD%91%E7%BB%9C-%E5%AE%89%E5%85%A8/92a2472e920f9f1365285d52d1bb9825_MD5.png)

+ **IP欺骗**：在IP分组中将IP设置为其他主机地址，来达到冒充目的。

+ **拒绝服务DoS**：向接收方恶意泛洪分组（例如SYN连接报文请求），淹没接收方，使其带宽或者系统资源耗尽，从而无法处理用户的连接请求。攻击者实施攻击时通常会选择分布式攻击方案，即会先入侵网络中的一些主机，组成僵尸网络，然后控制僵尸主机向目标发送分组。

  ![3f2eae4ae599b2afa5c31046a0522f7f_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E7%BD%91%E7%BB%9C%E9%80%9A%E4%BF%A1/assets/03.%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%BD%91%E7%BB%9C-%E5%AE%89%E5%85%A8/3f2eae4ae599b2afa5c31046a0522f7f_MD5.png)



## 预防对策

+ 预防扫描攻击：可以通过监控到达的网络流量，分析、识别出可疑活动（IP地址和端口被依次扫描）。
+ 预防嗅探攻击：每段广播介质只连接一台主机（如交换式以太网）；组织中的所有主机都周期性监测网络接口是否工作在混杂模式。
+ 预防IP欺骗：进行入口过滤，即路由器不转发源IP地址无效的IP分组（源IP地址不属于所连接的网络）。
+ 预防DoS攻击：追溯攻击源；使用SYN cookie技术预防SYN报文攻击。



# 密码学基础

## 加密过程

![e6a3b50d4b4f8f3b5aeb246e984c3a28_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E7%BD%91%E7%BB%9C%E9%80%9A%E4%BF%A1/assets/03.%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%BD%91%E7%BB%9C-%E5%AE%89%E5%85%A8/e6a3b50d4b4f8f3b5aeb246e984c3a28_MD5.png)

在一般的加密方式中，**加密算法通常是有公开标准的**，因此要防止第三者窃听，加密算法都会要求输入一个密钥，**基于该密钥对明文进行加密**。

为了描述的方便，我们用$m$表示明文，用$K_A(m)$表示利用密钥$K_A$加密$m$所得到的密文，用$K_B(K_A(m))$表示利用密钥$K_B$进行解密。



## 加密方式

一般常见的加密方式有两类：对称加密、非对称加密。

+ **对称加密**：通信双方使用一个相同的密钥进行加密，该密钥必须绝对保密。

  ![2a7d15d231c117b4a2dfea548813b606_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E7%BD%91%E7%BB%9C%E9%80%9A%E4%BF%A1/assets/03.%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%BD%91%E7%BB%9C-%E5%AE%89%E5%85%A8/2a7d15d231c117b4a2dfea548813b606_MD5.png)

+ **非对称加密**：通信双方都有两个密钥：公钥和私钥。公钥是公开可见的，私钥是绝对保密的。如下图所示，Alice向Bob发送明文时，要用Bob的公开密钥进行加密，Bob收到密文后使用自己的私钥进行解密。

  ![abd91ec2048dd538f266386c005e5467_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E7%BD%91%E7%BB%9C%E9%80%9A%E4%BF%A1/assets/03.%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%BD%91%E7%BB%9C-%E5%AE%89%E5%85%A8/abd91ec2048dd538f266386c005e5467_MD5.png)



# 密钥分发中心

**对称密钥加密**要求通信双方必须持有相同的对第三者保密的私钥，为了双方实体能够在网上建立共享密钥，需要可信任的**密钥分发中心（KDC）**来作为实体间的中介。

KDC实际上就相当于一个服务器，每个用户通过在KDC上注册来获得一个仅在该用户和KDC之间共享的密钥，通信的双方实体Alice和Bob，都只知道自己与KDC之间的对称密钥，可以分别与KDC进行加密通信，然后由KDC牵线转发保证两者间通信的安全性。

具体实现的通信过程如下：

+ Alice向KDC发送经过密钥$K_{A-KDC}$加密的密文，密文包含Alice和Bob的身份信息。
+ KDC利用密钥$K_{A-KDC}$解密得到Alice和Bob的身份信息，并产生本次会话的一个随机数$R1$。
+ KDC向Alice发送经过密钥$K_{A-KDC}$加密的密文，密文包含随机数和需要Alice转发给Bob的密文。
+ Alice利用密钥$K_{A-KDC}$解密获知会话随机数$R1$，然后将密文$K_{B-KDC}(A,R1)$（Alice无法解开）直接发送给Bob。
+ Bob利用$K_{B-KDC}$解密获知会话随机数$R1$和Alice的身份信息。
+ 至此，Alice和Bob已经互相知道对方的身份，并共享了随机数$R1$，之后Alice和Bob之间可以直接通信，$R1$作为他们本次会话的临时密钥进行对称加密。

上述过程可用下图形象表示。不难发现，该过程存在三种共享密钥$K_{A-KDC}$、$K_{B-KDC}$、$R1$，分别用于实现Alice与KDC、Bob与KDC、Alice与Bob三组对称加密会话。

![0e7bbd78bc3cdf7cc729150e780e9f32_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E7%BD%91%E7%BB%9C%E9%80%9A%E4%BF%A1/assets/03.%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%BD%91%E7%BB%9C-%E5%AE%89%E5%85%A8/0e7bbd78bc3cdf7cc729150e780e9f32_MD5.png)

问题：在一开始注册私钥的时候会不会有专门窃听的人去窃听大量私钥，然后再实体活动时，加班第三方机构。（可能之所以第三方可信任，就是不会被假扮）



# 公钥认证中心

**非对称加密**通信中，使用了两把钥匙：公钥和私钥。其中公钥在网络上是明文传输的，这就给了第三者冒充的机会，例如著名的**中间人攻击**过程：

+ Alice和Bob进行通信，中间人Trudy要窃听双方通信的内容，于是向Alice假扮Bob，向Bob假扮Alice。
+ Alice向假的Bob（Trudy）发送自己的身份信息，Trudy将信息转发给真正的Bob。
+ Bob返回给假的Alice（Trudy）一个随机数$R$，Trudy将该随机数转发给Alice，并且用自己的私钥$K_T^-$加密随机数发给Bob；Alice收到随机数后用自己的密钥$K_A^-$加密随机数发送给假的Bob（Trudy）。
+ Bob向假的Alice（Trudy）索要公钥，Trudy将自己的公钥$K_T^+$发送给Bob；Trudy向Alice索要公钥，Alice将自己的公钥$K_A^+$发送给假的Bob（Trudy）。
+ Bob向假的Alice（Trudy）发送的报文用Trudy的公钥加密，Trudy用自己的私钥解密后，再利用Alice的公钥转发加密转发给Alice。

可以发现，Alice之间Bob的通信报文都可以正常送达至对方，但是中途被中间人窃听转发，因此中间者攻击通常是非常隐蔽，难以察觉的。

![717ab18f2d8061cb07f557ca8e9b89d8_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E7%BD%91%E7%BB%9C%E9%80%9A%E4%BF%A1/assets/03.%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%BD%91%E7%BB%9C-%E5%AE%89%E5%85%A8/717ab18f2d8061cb07f557ca8e9b89d8_MD5.png)

问题：

+ 随机数R在非对称加密中的作用就是一开始进行身份认证，连接之后通信过程中应该都不需要了
+ 采用了CA之后，为什么不直接索要公钥来验证身份，这样就不用发随机数了
+ 用户发服务器用客户的私钥加密，服务器发给用户用客户的公钥加密，那么用户发给服务器的信息就可以被第三者解密，因为公钥是公开的。
+ P2P中，一次连接中，先发的人提供公钥



又再比如著名的“比萨恶作剧”：

+ Trudy创建邮件订单：

  ```
  Dear Pizza Store, Please deliver to me four pepperoni pizzas. 								--- From Bob.
  ```

+ Trudy利用自己的私钥签名订单，并向披萨店发送订单。
+ Trudy向披萨店发送她的公钥，披萨店认为这个公钥是Bob的。
+ 比萨店向Bob递送了4个腊肠比萨。
+ Bob根本就不喜欢腊肠。



通过上述两个案例，不难找到其中的根因：**公钥和身份信息没有进行绑定**。

假如中间人攻击中，Bob能通过某种方式验证公钥是否真正属于Alice，就能判断是否有人冒充了Alice；同理，如果披萨店能够验证公钥是否真正属于Bob，就能区分出恶作剧订单。



实体和公钥的绑定也是通过第三方信任机构来实现的，该机构称为**认证中心**（CA）。每个实体在CA上注册其公钥，并提供“身份证明”，然后CA创建绑定该实体和公钥的**证书**，用于申明“这是某实体的公钥”。

![1f7f06464e186d7226fa6eee42270061_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E7%BD%91%E7%BB%9C%E9%80%9A%E4%BF%A1/assets/03.%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%BD%91%E7%BB%9C-%E5%AE%89%E5%85%A8/1f7f06464e186d7226fa6eee42270061_MD5.png)

证书一般包含以下内容：证书序列号（唯一发行号）、证书的持有者信息、证书的发行者信息、有效期、公钥信息（数字签名，利用CA私钥加密的实体公钥，只能用对应的CA公钥解开）、签名算法。

有了CA机构签发的证书之后，当Alice想要Bob的公钥时，首先Bob发送给Alice他的公钥证书，Alice根据CA公钥解密证书中签名的公钥，获得Bob公钥。

## 混合加密

解决加密问题。

+ 在通信建立前使用**非对称加密**的方式交换“会话密钥”，之后不再使用非对称加密。
+ 通信过程中全部使用“会话密钥”进行**对称加密**。

采用**混合加密**的原因：

+ 对称密钥只使用一个密钥，运算速度快，但是密钥的交换需要借助密钥分发中心KDC。
+ 非对称密钥加密使用公钥和私钥，密钥交换安全，但是运算速度慢。
