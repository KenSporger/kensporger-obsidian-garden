# 概述

和传输层负责进程间的网络传输不同，网络层负责源主机到目的主机数据段的交付，在发送方，网络层将数据段封装到**数据报（Datagram）**中，在接收方，网络层则向传输层交付数据段。网络层属于**非端到端层**，网络中的每个主机和路由器都运行着网络层协议。

网络层的核心功能：

+ **转发**：将分组从路由器的输入端口转移到合适的输出端口。为了确定输出端口，每个路由器都事先建立了一张**转发表**。
+ **路由**：利用**路由算法**确定分组从源到目的需要经过的节点路径。
+ **连接建立**：传输层的连接建立是在两端建立逻辑连接；而实际路径上的路由器等设备都需要参与到连接中来，这部分工作则是由网络层负责的。

网络层需要为传输层提供服务，在不同的网络架构中，会采用不同的服务模型。例如，Internet中，网络层向传输层提供“尽力服务”，在带宽、丢包、乱序、延迟方面都不提供可靠保障。而ATM网络架构中，则定义了多种服务模型，这些模型或多或少具备了一些传输上的保障能力。

![计算机科学/网络通信/assets/02. 计算机网络-网络层/6b4898e0e24e1fae134b4463c0108836_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E7%BD%91%E7%BB%9C%E9%80%9A%E4%BF%A1/assets/02.%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%BD%91%E7%BB%9C-%E7%BD%91%E7%BB%9C%E5%B1%82/6b4898e0e24e1fae134b4463c0108836_MD5.png)

尽管存在多种网络层服务模型，但我们可以大致将它们分为两大类：

+ **无连接服务**：不事先为系列分组的传输确定传输路径，每个分组在传输时独立确定路径，所以同一对发送方和接收方之间的不同分组的传输路径可能不同，这也意味着分组到达目的时会乱序。采用该类服务的网络称为**数据报网络**。
+ **连接服务**：事先为系列分组的传输确定从源主机到目的经过的路径（建立连接），然后沿该路径（连接）传输系列分组，在该服务下，分组的顺序会得到保障（先发的必然先到），在传输结束后，服务要负责拆除连接。采用该类服务的网络称为**虚电路网络**。

需要强调的是，**数据报网络和虚电路网络都属于分组交换网络，它们的关系类似于传输层的TCP和UDP，但是因为属于不同的层，故而有着本质的区别**。



# 虚电路网络

虚电路网络和电路交换技术有些许相似，通信过程也包括：呼叫建立=>数据传输=>拆除呼叫。和电路连接技术不同的是虚电路属于分组交换技术，每个分组的传输都有机会利用链路的全部带宽。

连接建立后，网络如何记忆该虚电路呢？事实上，沿路的每段链路都会有一个**虚电路号（VCID）**，沿路的每个网络层设备利用**虚电路转发表**记录输入VCID和其对应的输出VCID，如下图所示。

# 数据报网络

Internet采用的是网络层无连接的数据报网络，每个分组传输过程中一直携带着目的地址，路由器根据分组的目的地址和自己的**数据报转发表**选择合适的出口转发分组。

![计算机科学/网络通信/assets/02. 计算机网络-网络层/88bf82226d34d8d39df104f9948b8349_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E7%BD%91%E7%BB%9C%E9%80%9A%E4%BF%A1/assets/02.%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%BD%91%E7%BB%9C-%E7%BD%91%E7%BB%9C%E5%B1%82/88bf82226d34d8d39df104f9948b8349_MD5.png)

数据报转发表建立的是目的地址和输出链路的映射关系。因为IP地址多达40亿多种，所以单独为每个IP分别建立映射是不现实的。如下图所示，转发表只是为每个地址范围建立映射，如同邮政快递，先是按照省份分发邮件，然后按照市级下发，这个过程中，地址范围逐渐缩小。

![计算机科学/网络通信/assets/02. 计算机网络-网络层/ed465b466b3e3c61264e82b9bda68b1d_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E7%BD%91%E7%BB%9C%E9%80%9A%E4%BF%A1/assets/02.%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%BD%91%E7%BB%9C-%E7%BD%91%E7%BB%9C%E5%B1%82/ed465b466b3e3c61264e82b9bda68b1d_MD5.png)

理想的地址范围划分是每个范围不发生重叠，但是实际中并不是这么“完美”。例如下图的例子，接口2的范围包含了接口1的范围，这样的情况下，采用**最长前缀匹配优先**，即优先选择与分组目的地址匹配前缀最长的出口，从而使得范围尽可能的小。

![计算机科学/网络通信/assets/02. 计算机网络-网络层/128915672f3321c55def3c57421faa44_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E7%BD%91%E7%BB%9C%E9%80%9A%E4%BF%A1/assets/02.%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%BD%91%E7%BB%9C-%E7%BD%91%E7%BB%9C%E5%B1%82/128915672f3321c55def3c57421faa44_MD5.png)



实际应用中，到底是采用数据报网络还是虚电路网络取决于应用需求。数据报网络将数据可靠性保障交予传输层去发挥，从而**简化了网络，但复杂了边缘**，像Internet的端系统通常都是性能较好、功能强大的计算机，所以完全可以胜任自适应、性能控制、差错恢复等工作。而虚电路网络则是**简化边缘，复杂了网络**，采用虚电路的ATM，是从电话网络演化而来的，它的核心业务是实时通话，对网络质量要求较高，并且不希望端系统过于复杂，所以只能采用虚电路方案。



# IP协议

## IP数据报格式

![计算机科学/网络通信/assets/02. 计算机网络-网络层/1b62cb16c503dc1b660c0742d40a080f_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E7%BD%91%E7%BB%9C%E9%80%9A%E4%BF%A1/assets/02.%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%BD%91%E7%BB%9C-%E7%BD%91%E7%BB%9C%E5%B1%82/1b62cb16c503dc1b660c0742d40a080f_MD5.png)

+ 版本号：占4位，IPv4为4，IPv6为6。

+ 首部长度：占4位，**单位为4字节**，标准IP报可变部分没有内容，因此首部长度为20（5×4）字节。

+ 服务类型（区分服务）：指示期望获得哪种类型的服务，一般情况不使用，即值为00H。

+ 总长度：首部+数据的总字节数（最大数据长度=65535-20=65515字节）。

+ 标识：标识一个IP分组，同一个IP分组的不同分片具有相同标识。

+ 标志位：包含两个标志位DF和MF。

  + DF=1：禁止分片；

    DF=0：允许分片；

  + MF=1：非最后一片；

    MF=0：最后一片（或未分片）；

+ 片偏移：一个IP分片数据部分相对于原IP分组数据部分的偏移量，以8字节为单位。

+ 生存时间：IP分组在网络中可以通过的路由器数（或跳步数），路由器转发一次分组，TTL减1，如果TTL=0，路由器则丢弃该IP分组。

+ 协议：指示封装的是哪个协议的数据包，6为TCP，17为UDP（TCP和UDP采用同一IP数据报格式）。

+ 选项字段：很少使用，可以携带时间戳、路由记录等信息。

+ 填充：保证首部长度是4字节的倍数。





## IP分片

![计算机科学/网络通信/assets/02. 计算机网络-网络层/f8af943da8cefa7978e1c6326d3bad8f_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E7%BD%91%E7%BB%9C%E9%80%9A%E4%BF%A1/assets/02.%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%BD%91%E7%BB%9C-%E7%BD%91%E7%BB%9C%E5%B1%82/f8af943da8cefa7978e1c6326d3bad8f_MD5.png)

网络链路存在MTU（最大传输单元）——链路层数据帧可封装数据的上限，并且不同链路的MTU也不同。当大IP分组向较小MTU链路转发时，需要将IP数据报分片，所有IP分片到达目的主机后再进行重组。

![计算机科学/网络通信/assets/02. 计算机网络-网络层/2ca57bea554c69c00f251eb005a5232c_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E7%BD%91%E7%BB%9C%E9%80%9A%E4%BF%A1/assets/02.%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%BD%91%E7%BB%9C-%E7%BD%91%E7%BB%9C%E5%B1%82/2ca57bea554c69c00f251eb005a5232c_MD5.png)

IP首部的相关字段用于标识分片以及确定分片的相对顺序，这些字段包括：总长度、标识、标志位、片偏移。

+ 同一分组的分片应该具有相同标识；
+ 未分片的分组其MF=0，且片偏移也等于0；
+ 经过分片的分组其最后一块分片通过标志MF确定；
+ 片偏移字节数是8的倍数，这意味着分片数据部分的长度需要是8的倍数；

IP分片的过程描述如下：

+ 假设原IP分组总长度为L，链路的MTU为M；

+ 若L>M，且DF=0，则需要分片；

+ 分片时，每个分片的标识复制原IP分组的标识；

+ 通常分片时，除最后一个分片，其他分片均分为MTU允许的最大分片；

+ 一个最大分片可封装的数据应该是8字节的倍数，因此，一个最大分片可封装的数据为：
  $$
  d=\left \lfloor \frac{M-20}{8} \right \rfloor×8
  $$
  
+ 需要的总片数为：
  $$
  n=\left \lceil \frac{L-20}{d} \right \rceil
  $$
  
+ 每片的片偏移字段取值为：
  $$
  F_i = \frac{d}{8}×(i-1)
  $$

+ 每片的总长度字段为：
  $$
  L_i = \begin{cases}
  d+20 & \text{,} 1 \leq i < n\\ 
  L-(n-1)d & \text{,} i = n
  \end{cases}
  $$





## IP编址

IP是对主机/路由器的接口进行编址的，主机通常只有一个或两个接口，路由器通常有多个接口。

IP地址由**网络号**和**主机号**两部分构成，具有相同网络号的设备接口处于同一个**IP子网**内，**在同一个IP子网内的设备可以不跨越路由器就可以彼此通信**，而处于不同子网的设备通信必须经过路由器转发。

## 子网划分

![计算机科学/网络通信/assets/02. 计算机网络-网络层/2d9e31d6740248c1d48b4e9f8ff589b8_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E7%BD%91%E7%BB%9C%E9%80%9A%E4%BF%A1/assets/02.%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%BD%91%E7%BB%9C-%E7%BD%91%E7%BB%9C%E5%B1%82/2d9e31d6740248c1d48b4e9f8ff589b8_MD5.png)

子网划分是在已有的ABC类IP子网的基础上区分出范围更小的子网。为了划分，将主机号的高位单独拿出来作为**子网号**，于是IP地址由网络号、子网号和主机号构成。例如，在公司中，可能使用某个固定NetID的子网作为公司内部网络，公司为了区分不同的部门，为每个部门分配一个SubID，这样每个部门就是一个单独子网。

为了确定一个IP地址是否被划分了子网，以及用多少位来划分子网，引入了**子网掩码**。子网掩码的取值就是NetID和SubID位都取1，HostID位全取0。例如：

+ A网的默认子网掩码为：255.0.0.0
+ B网的默认子网掩码为：255.255.0.0
+ C网的默认子网掩码为：255.255.255.0

借用HostID高位部分的3比特来划分子网的C网的子网掩码为：255.255.225.224；一共可以划分出8个子网，每个子网的地址数有32个，如192.168.0.32~192.168.0.63就表示SubID=1的子网地址范围，而192.168.0.32代表子网本身，192.168.0.63是该子网广播地址，所以有效可分配主机地址数只有30个。因此，经过子网划分后，可分配的地址数会减少。

![计算机科学/网络通信/assets/02. 计算机网络-网络层/faac74f589e68ec73944b966770571b2_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E7%BD%91%E7%BB%9C%E9%80%9A%E4%BF%A1/assets/02.%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%BD%91%E7%BB%9C-%E7%BD%91%E7%BB%9C%E5%B1%82/faac74f589e68ec73944b966770571b2_MD5.png)

经过子网划分以后，路由器通过将IP分组的目的IP地址和子网掩码**按位与**运算，就可以提取出子网地址，从而确定应该将IP分组转发到哪个子网中去。例如，目的IP地址为172.32.1.112，子网掩码为255.255.254.0，那么子网地址应该为172.32.0.0。



## 无类地址CIDR

CIDR全称是无类域间路由。它消除了传统的A类、B类和C类地址界限，融合了子网地址和子网掩码，方便子网划分。无类地址的格式为：a.b.c.d/x，其中x表示前缀长度（NetID+SubID长度），例如128.14.24.5/20表示该IP地址属于地址为128.14.16.0的子网，子网掩码为255.255.240.0。

无类地址相比有类地址要更灵活，可以按照需要分配前缀长度，而当把一个有类地址分配给一个公司后，该公司可能不能最大化利用这个地址范围（比如分配一个A类地址，但公司实际的主机数量可能远小于A类地址能够提供的最大主机数），从而造成浪费。

另一方面，无类地址通过改变前缀长度可以很容易直观地形成层级结构，靠近网络核心的路由器地址其地址前缀可以较短，而接近边缘的路由器其前缀长度可以较长，这就能实现**路由聚合**，从而提高路由效率。



## 路由聚合

![计算机科学/网络通信/assets/02. 计算机网络-网络层/d5c7b5bf496f757d2e7e9c761b55c7db_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E7%BD%91%E7%BB%9C%E9%80%9A%E4%BF%A1/assets/02.%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%BD%91%E7%BB%9C-%E7%BD%91%E7%BB%9C%E5%B1%82/d5c7b5bf496f757d2e7e9c761b55c7db_MD5.png)

如上图所示，转发表中原本有三个子网映射都映射到接口2，那么在检索转发表的时候，就需要匹配多次；利用路由聚合，我们可以将输出接口相同的不同子网聚合成一个大子网，这样就减少了转发表的大小和检索时间。

再比如下例，Fly-By-Night-ISP连接着组织0、组织2、组织7等等，通过路由聚合，这些组织网络都被聚合成一个大子网200.23.16.0/20。当互联网中有发送给这些组织的分组时，不用知道Fly-By-Night-ISP管理着哪些组织，只需要知道这个大子网即可，当IP分组的目的地址属于该大子网时，互联网就把该分组交给Fly-By-Night-ISP去转发。

ISPs-R-Us管理的组织1不属于大子网200.23.16.0/20，但是其IP地址能跟它进行前缀匹配，所以如果ISPs-R-Us不告诉互联网自己管理着200.23.18.0/23，那么发给组织1的分组就会被错交给Fly-By-Night-ISP；相反，如果互联网知道200.23.18.0/23是由ISPs-R-Us管理的，那么根据**最长前缀匹配优先**，互联网会优先选择ISPs-R-Us进行分组交付。

# DHCP协议

## 协议功能



一个主机可以通过两种方式获取IP地址：静态配置、使用DHCP协议配置。

静态配置允许用户手动配置主机的IP地址、子网掩码、默认网关和DNS服务器。

![计算机科学/网络通信/assets/02. 计算机网络-网络层/58a53e0edd90054f1faa29a4357d47f2_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E7%BD%91%E7%BB%9C%E9%80%9A%E4%BF%A1/assets/02.%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%BD%91%E7%BB%9C-%E7%BD%91%E7%BB%9C%E5%B1%82/58a53e0edd90054f1faa29a4357d47f2_MD5.png)

DHCP协议全称为动态主机配置协议，能使主机从DHCP服务器中动态获取IP地址、子网掩码、默认网关和DNS服务器地址信息。主机从DHCP服务器拿到的IP地址不是永久的，而是有租赁期的，当租赁期限到达时，主机可以向服务器请求续租；DHCP协议允许地址重用，即在某台主机离线时，DHCP服务器可以将它的地址暂时租赁给另一台在线主机。

需要注意的是，虽然在网络层中才讲述DHCP协议，但是**DHCP属于应用层协议**。



## 工作过程

![计算机科学/网络通信/assets/02. 计算机网络-网络层/f86a3816b9c10f75a3d63ebe4a153bfe_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E7%BD%91%E7%BB%9C%E9%80%9A%E4%BF%A1/assets/02.%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%BD%91%E7%BB%9C-%E7%BD%91%E7%BB%9C%E5%B1%82/f86a3816b9c10f75a3d63ebe4a153bfe_MD5.png)

1. 当主机希望加入该子网时，它还不具有IP地址，也不知道网络中DHCP服务器地址，因此主机需要广播“DHCP discover”（发现报文），源地址设置为0.0.0.0（在本网中表示本机），目的地址为255.255.255.255（本网广播地址）。
2. 该子网中可能存在多个DHCP服务器，它们都会利用"DHCP offer"（提供报文）进行响应，源地址设置为服务器自己的地址；因为主机还没有分配地址，所以必须采用广播，即目的地址还是255.255.255.255。yiaddr字段就是服务器提供给主机的IP地址。
3. 主机接收到某个服务器的提供报文后，还不能直接使用该地址，必须要广播“DHCP request”（请求报文），“拒绝”其他DHCP服务器提供的地址（服务器被拒绝后收回地址资源）。
4. 提供地址的DHCP服务器广播"DHCP ack"（确认报文），主机收到后便可以使用该IP地址了。



# NAT协议



## 协议原理

NAT全称为网络地址转换协议，主要解决子网私有地址的主机无法和互联网主机通信的问题。其实现方式有三步：

+ 利用NAT路由器的IP地址和新端口号替换每个外出IP数据报的源IP地址和端口号；
+ 将每对NAT IP地址、新端口号与源IP地址、端口号的替换信息存储到NAT转换表中；
+ 根据NAT转换表，利用源IP地址和端口号替换每个进入内网IP数据报的目的IP地址和目的端口号；

![计算机科学/网络通信/assets/02. 计算机网络-网络层/8ec2e18ce9178fd314889bf1fbe498a1_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E7%BD%91%E7%BB%9C%E9%80%9A%E4%BF%A1/assets/02.%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%BD%91%E7%BB%9C-%E7%BD%91%E7%BB%9C%E5%B1%82/8ec2e18ce9178fd314889bf1fbe498a1_MD5.png)



## 主要争议

NAT协议在现在的IPv4网络发挥着非常重要的作用，但是也一直受到一些争议，例如：

+ 路由器应该只处理第三层功能，但是NAT协议要求它更改传输层负责的端口号；
+ 违背了端到端通信的原则，例如在P2P应用中，应用开发者必须考虑NAT的存在（如何主动访问子网中的用户主机）；
+ 地址短缺问题应该要由IPv6来解决；



## 内网穿透

![计算机科学/网络通信/assets/02. 计算机网络-网络层/0bddb8ce3ea3d89fc7596ffaec50843a_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E7%BD%91%E7%BB%9C%E9%80%9A%E4%BF%A1/assets/02.%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%BD%91%E7%BB%9C-%E7%BD%91%E7%BB%9C%E5%B1%82/0bddb8ce3ea3d89fc7596ffaec50843a_MD5.png)

当互联网中的客户机想要连接处于内网中服务器时，必须进行**内网穿透**。内网穿透主要有三种方案：

+ 静态配置NAT：将特定端口的连接请求固定转发给服务器，互联网主机就通过路由器IP和该端口来访问服务器。

+ 利用即插即用（UPnP）互联网网关设备协议（IGD）自动配置NAT：处于内网中的服务器学习到NAT的公共IP地址，然后主动在NAT转换表中增删端口映射，然后...

+ 中继服务器：NAT内部的客户与中继服务器建立连接，外部客户也与中继服务器建立连接，中继服务器桥接两个连接的分组。

# 动态路由算法

## 概述

路由器转发IP数据报需要依靠转发表，而转发表中的信息是通过**路由算法**确定的。路由算法的作用就是**确定去往每一个目的网络的最佳路径**。

在路由算法中，网络被抽象为图（节点和边的集合），每段链路都有其费用，这个费用可以都是1，也可以是带宽的倒数、拥塞程度等。而源到目的的最佳路径就是要满足总费用最小。

根据算法运行时对信息的需求程度，可以把算法分成两类：一种是需要掌握网络拓扑的全局信息的，另一种则只要掌握邻近节点的局部信息；前者典型的算法就是**链路状态路由算法**，后者典型的算法是**距离向量路由算法**。



## 链路状态路由算法

### Dijkstra算法

![计算机科学/网络通信/assets/02. 计算机网络-网络层/0423a715bf88e3a3702483c97a11f51d_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E7%BD%91%E7%BB%9C%E9%80%9A%E4%BF%A1/assets/02.%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%BD%91%E7%BB%9C-%E7%BD%91%E7%BB%9C%E5%B1%82/0423a715bf88e3a3702483c97a11f51d_MD5.png)

+ N'：代表闭集合，集合中的节点都已找到最短路径；
+ D(?)：节点?到u的代价；
+ p(?)：当前下路径节点?的前序节点；
+ 自由节点：不处于闭集合中的节点。

算法过程如下：

1. 在算法一开始，初始化节点u的代价为0，其他节点的代价为$\infin$，闭集合为空。
2. 选择代价最小的自由节点（step=0时就是节点u），记作A，将其加入闭集合，并遍历与其相邻的自由节点，记作B，更新它们的代价为$D(B)=min\{D(B),D(A)+D(A,B)\}$，其中$D(A,B)$表示节点A和B之间链路的代价。如果更新后代价变小了，则设置节点B的前序节点为A。
3. 不断循环执行第2步，直到该网络中不存在自由节点。



### 震荡问题

链路状态路由算法存在震荡的可能，假设链路费用是该链路目前的通信量，如第一张图所示，B->A的通信量为1+e，B->C->D->A的通信量为1；所以下一次如果B的分组要发到A，那么就会选择B->C->D->A这条链路，如第二张图所示；同时，在下一次如果路由器D有分组要发到A，则会选择D->C->B->A链路，如图三所示。

那么假如一开始路由器C将分组通过C->B->A发到路由器A，但在分组到达路由器B时，转发表更新，那么该分组会被路由器B通过链路B->C->D->A路由到节点A，然后分组到达路由器D时又被路由回节点B，这样该分组就在网络中徘徊永远到不了路由器A，最终因为达到多跳上限而被丢弃。
