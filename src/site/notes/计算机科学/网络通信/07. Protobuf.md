# 定义

ProtoBuf是一种**语言无关**（支持多种编程语言）、**平台无关**、**可扩展**的**序列化**结构数据的方法，它可用于**通信**协议、数据**存储**等。相比于XML和JSON，它更快、更小、更为简单。

+ **序列化**：将结构数据或对象转换为能够被存储和网络传输的格式。序列化简单来说可以理解为将一个对象转换为一串比特流，而反序列化则是将一串比特流结构化成键值对（对象）。
+ **扩展性**：当我们更新数据结构之后，并不影响和破坏原有的旧程序。



# 基本原理

用户在.proto文件中定义rotocol buffer message 类型，来指定如何对信息进行结构化。每一个message都是一些字段（键值对）的集合，如下图所示。每一个字段由类型、名称和唯一编号组成，其中字段类型甚至可以是message类型，这意味着可以嵌套地构建数据。

```protobuf
message Person {
  required string name = 1;
  required int32 id = 2;
  optional string email = 3;

  enum PhoneType {
    MOBILE = 0;
    HOME = 1;
    WORK = 2;
  }

  message PhoneNumber {
    required string number = 1;
    optional PhoneType type = 2 [default = HOME];
  }

  repeated PhoneNumber phone = 4;
}
```

一旦定义了 messages，就可以在 .proto 文件上运行 protocol buffer 编译器来生成指定语言的数据访问类。例如，如果使用C++，那么编译将生成一个名为Person的类，这个类还提供了访问字段的方法，用户可以像下面这样去使用：

```c++
Person person;
person.set_name("John Doe");
person.set_id(1234);
person.set_email("jdoe@example.com");
fstream output("myfile", ios::out | ios::binary);
person.SerializeToOstream(&output);
```

用户可以在 message 格式中添加新字段，而不会破坏向后兼容性;旧的二进制文件在解析时只是忽略新字段。因此，如果你的通信协议使用 protocol buffers 作为其数据格式，则可以扩展协议而无需担心破坏现有代码。



# 对比XML

ProtoBuf相比于XML的优势有：

+ 更简单；
+ 小3~10倍；
+ 快20~100倍；
+ 更加清晰明确；
+ 自动生成更易于使用；

例如，为一个具有姓名和电子邮件的人建模，XML中，用户需要：

```xml
<person>
    <name>John Doe</name>
    <email>jdoe@example.com</email>
</person>
```

而对应的protocol buffer message是：

```protobuf
person {
  name: "John Doe"
  email: "jdoe@example.com"
}
```

不要忘了这个消息文件会被编译为二进制格式，它可能是 28 个字节长，需要大约 100-200 纳秒来解析。如果删除空格，XML版本至少为 69 个字节，并且需要大约 5,000-10,000 纳秒才能解析。

此外，比起XML，操作Protocol Buffer更为容易：

```c++
cout << "Name: " << person.name() << endl;
cout << "E-mail: " << person.email() << endl;
```

而使用XML，必须执行以下操作：

```c++
cout << "Name: "
     << person.getElementsByTagName("name")->item(0)->innerText()
     << endl;
cout << "E-mail: "
     << person.getElementsByTagName("email")->item(0)->innerText()
     << endl;
```



# 语法

## 指定proto语法版本

如果不指定，默认会使用`proto2`版本的语法。

```
syntax = "proto3";
```



## 字段编号

这些字段编号用于在[消息二进制格式中](https://developers.google.com/protocol-buffers/docs/encoding)标识您的字段，一旦您的消息类型被使用，就不应更改。1 到 15 编号范围内的字段其编号和类型一共占用一个字节，16 到 2047编号范围内的字段则占用两个字节，因此应该为非常频繁出现的消息元素保留数字 1 到 15（也要为将来可能添加的频繁出现的元素留出一些空间）。



## 字段规则

`proto3`有两种规则：

+ `singular`：消息可以有个零个或一个此字段，这是默认规则。

+ `repeated`：该字段可以在消息中重复多次（可以看做是一个可扩充的数组）。



## 定义多个消息类型

可以在单个`.proto`文件中定义多种消息类型。多个相关的消息，可以放在同一个proto文件中——例如，如果定义与`SearchResponse`消息类型相对应的回复消息格式，可以将其添加到相同的`.proto`:

```protobuf
message SearchRequest {
  string query = 1;
  int32 page_number = 2;
  int32 result_per_page = 3;
}

message SearchResponse {
 ...
}
```





## 保留字段

如果修改协议时想要去掉某个字段，不应当直接将其删除，这会导致旧协议的使用者在不知情的情况下再次使用该字段。正确的做法是将在删除字段后将相应编号或者字段名称设为保留。

```protobuf
message Foo {
  reserved 2, 15, 9 to 11;
  reserved "foo", "bar";
}
```



## 编译产物

对于C++，一个proto文件编译后生成一对.h和.cc文件。其中定义的每一个message类型都会生成对应的类。



## 枚举

一个字段可以是枚举类型，来预先定义该字段的取值。

```protobuf
message SearchRequest {
  string query = 1;
  int32 page_number = 2;
  int32 result_per_page = 3;
  enum Corpus {
    UNIVERSAL = 0;
    WEB = 1;
    IMAGES = 2;
    LOCAL = 3;
    NEWS = 4;
    PRODUCTS = 5;
    VIDEO = 6;
  }
  Corpus corpus = 4;
}
```





## 嵌套

```protobuf
message Outer {                  // Level 0
  message MiddleAA {  // Level 1
    message Inner {   // Level 2
      int64 ival = 1;
      bool  booly = 2;
    }
  }
  message MiddleBB {  // Level 1
    message Inner {   // Level 2
      int32 ival = 1;
      bool  booly = 2;
    }
  }
}
```



## 包说明符

```protobuf
package Foo;
message Open{

}
```

如此定义之后，C++中需要使用`Foo::Open`来访问。

+ 从txt文件中以二进制方式读取并解析打印，然后以用户交互创建一个Person对象，然后再重新以二进制形式写入到txt文件中。

  ```c++
  #include<iostream>
  #include<fstream>
  #include<string>
  #include "proto/addressbook.pb.h"
  
  using namespace std;
  
  void CreatePerson(tutorial::Person* person)
  {
      cout << "Enter person id: ";
      int id;
      cin >> id;
      person->set_id(id);
  
      cout << "Enter name: ";
      cin >> *person->mutable_name();
      
      cout << "Enter email: ";
      string email;
      getline(cin, email);
      person->set_email(email);
  
      while (true)
      {
          cout << "Enter a phone number: ";
          string number;
          getline(cin, number);
          if (number.empty())
          {
              break;
          }
          tutorial::Person::PhoneNumber* phone_number = person->add_phones();
          phone_number->set_number(number);
          
          cout << "Is this a mobile, home, or work phone?";
          string type;
          getline(cin, type);
          if (type == "mobile")
          {
              phone_number->set_type(tutorial::Person::MOBILE);
          }
          else if (type == "home")
          {
              phone_number->set_type(tutorial::Person::HOME);
          }
          else if (type == "work")
          {
              phone_number->set_type(tutorial::Person::WORK);
          }
      }   
  }
  
  void ListPeople(const tutorial::AddressBook& addr_book)
  {
      for (int i = 0; i < addr_book.people_size(); i++)
      {
          const tutorial::Person& person = addr_book.people(i);
          cout << "Id: " << person.id() << endl;
          cout << "Name: " << person.name() << endl;
          if (person.has_email()) {
             cout << "E-mail address: " << person.email() << endl;
          }
          for (int j = 0; j < person.phones_size(); j++) {
              const tutorial::Person::PhoneNumber& phone_number = person.phones(j);
  
              switch (phone_number.type()) {
                  case tutorial::Person::MOBILE:
                      cout << "Mobile phone #: ";
                      break;
                  case tutorial::Person::HOME:
                      cout << "Home phone #: ";
                      break;
                  case tutorial::Person::WORK:
                      cout << "Work phone #: ";
                      break;
              }
              cout << phone_number.number() << endl;
          }
      }
  }
  
  int main()
  {
      GOOGLE_PROTOBUF_VERIFY_VERSION;
  
      string filename = "../address.txt";
      tutorial::AddressBook addr_book;
      {
          fstream input(filename, ios::in | ios::binary);
          if (!input)
          {
              cout << "fstream error!";
              return 0;
          }
          else if (!addr_book.ParseFromIstream(&input))
          {
              cout << "parse error!";
              return 0;
          }
      }
      ListPeople(addr_book);
      CreatePerson(addr_book.add_people());
  
      {
          fstream output(filename, ios::out | ios::binary | ios::trunc);
          if (!addr_book.SerializeToOstream(&output))
          {
              cout << "serialize error!";
              return 0;
          }
      }
  
      google::protobuf::ShutdownProtobufLibrary();
  
      return 0;
  }
  ```

  

## 兼容性

在新版本协议中，应当遵循：

+ 不更改任何现有字段的标签编号；
+ 不得添加或删除任何必填字段；
+ 可以删除可选或重复字段；
+ 可以添加新的可选或重复字段，但必须使用新的标签编号（即从未在此协议缓冲区中使用过的标签号，甚至被删除的字段也没有使用过）。

对于旧代码，可以忽略任掉何新字段，被删除的可选字段将仅具有其默认值，而被删除的重复字段将为空。

而在采用新协议的代码中，可能会收到旧协议消息，所以对于新添加的可选字段，要明确检查它们是否设置为`has_`，或者在`.proto`文件中提供合理的默认值`[default = value]`在标签号之后（如果没有为可选元素指定默认值，则使用特定于类型的默认值）。

另请注意，如果添加了一个新的重复字段，新协议代码将无法判断它是留空（新协议下）还是根本没有设置（旧协议下），因为它没有`has_`标志。



## 反射

协议消息类提供的一项关键特性是*反射*。您可以遍历消息的字段并操作它们的值，而无需针对任何特定的消息类型编写代码。使用反射的一种非常有用的方法是将协议消息与其他编码（例如 XML 或 JSON）相互转换。反射的更高级用途可能是找到相同类型的两个消息之间的差异，或者开发一种“协议消息的正则表达式”，您可以在其中编写与某些消息内容匹配的表达式。如果您发挥自己的想象力，就有可能将协议缓冲区应用于比您最初预期的更广泛的问题！

反射由[`Message::Reflection`接口](https://developers.google.com/protocol-buffers/docs/reference/cpp/google.protobuf.message#Message.Reflection)提供。



# 编码



## 整形压缩

ProtoBuf使用了最常见的整数压缩方法，即每个字节的最高位作为前导标志位，需要注意的是压缩编码采用小端模式，即低地址存储整数的低字节。例如：

```
1010 1100 0000 0010
```

首先，去掉前导位，

```
1010 1100 0000 0010
→010 1100  000 0010
```

然后颠倒一下字节顺序，变为

```
00 0001 0010 1100
```

该序列表示整数300。



## ZigZag编码

有符号整形采用ZigZag方式编码，该方法可用下式表示。
$$
f(n)=\begin{cases}
2*n & \text{,}x >= 0\\ 
2*|n|-1 & \text{,}x<0 
\end{cases}
$$


对于有符号32位整数，编码算法为：

```
(n << 1) ^ (n >> 31)
```

其中如果n大于等于0，那么（n>>31）的结果就是0，然后（n<<1）和0异或的结果就是（n<<1）本身，即编码后为原来的两倍。如果n小于0，那么（n>>31）的结果就是全1，即-1，（n<<1）和-1异或的结果就是2|n|-1。

这样编码后，就可用更大的无符号数来表示有符号数了，只是有效范围减少了一半；但使用无符号数表示的优点就是具备较多无效的前导0。



## 固定长度

wire-type=1和wire-type=5的类型都使用固定长度表示，不进行压缩编码。



## Length-delimited类型

使用Length表示Vlaue的字节数，Length本身也采用Varint编码。



## repeated压缩

对于Varint、64-bit、32-bit类型（三个统称为标量）的repeated字段，可以进行打包压缩，因为它们共用一个编号且类型相同，没有必要为它们保留键，编码的结果就是从Tag-Value-Tag-Value-Tag-Value压缩为Tag-Value-Value-Value。





## 消息结构

ProtoBuf消息是一系列键值对，消息的二进制版本并不使用字段本身作为键，而是使用字段的编号。所以解码端如果要找回字段的名称和类型只能通过.proto文件的消息定义来实现。

ProtoBuf的消息采用了TLV（Tag-Length-Value）的结构，其中Tag采用Varint方式编码，即最高位用作标志位。一个Tag由field-number（字段编号）和wire-type（字段类型）构成，类型用三个比特表示，有以下取值。

| Type | Meaning          | Used For                                                 |
| :--- | :--------------- | :------------------------------------------------------- |
| 0    | Varint           | int32, int64, uint32, uint64, sint32, sint64, bool, enum |
| 1    | 64-bit           | fixed64, sfixed64, double                                |
| 2    | Length-delimited | string, bytes, embedded messages, packed repeated fields |
| 3    | Start group      | groups (deprecated)                                      |
| 4    | End group        | groups (deprecated)                                      |
| 5    | 32-bit           | fixed32, sfixed32, float                                 |

Length专用于Length-delimited类型，其他情况下省略。Value则代表字段值。

## 字段顺序

字段编号可以在.proto文件中以任何顺序使用，该顺序对消息的序列化没有任何影响。事实上，当消息被序列化时，其字段的写入顺序是不确定的，但ProtoBuf保证能够以任何顺序来解析字段（通过编号和字段的对应的关系）。这个规则将产生许多容易导致通信错误的影响，例如：

- 不要假设序列化消息的字节输出是稳定的。对于具有表示其他序列化协议缓冲区消息的可传递字节字段的消息尤其如此。

- 默认情况下，在同一个协议缓冲区消息实例上重复调用序列化方法可能不会返回相同的字节输出；即默认序列化不是确定性的。

  - 确定性序列化仅保证特定二进制文件的相同字节输出。字节输出可能会因二进制文件的不同版本而异。

- 对于协议缓冲区消息实例，以下检查可能会失败

  - `foo.SerializeAsString() == foo.SerializeAsString()`
  - `Hash(foo.SerializeAsString()) == Hash(foo.SerializeAsString())`
  - `CRC(foo.SerializeAsString()) == CRC(foo.SerializeAsString())`
  - `FingerPrint(foo.SerializeAsString()) == FingerPrint(foo.SerializeAsString())`

- 我这里还有一些示例场景中逻辑上等效协议缓冲区中的消息

  可序列化到不同的字节输出。

  - `bar` 由将某些字段视为未知的旧服务器进行序列化。
  - `bar` 由以不同编程语言实现的服务器序列化并以不同顺序序列化字段。
  - `bar` 有一个以非确定性方式序列化的字段。
  - `bar` 有一个字段，用于存储以不同方式序列化的协议缓冲区消息的序列化字节输出。
  - `bar` 由新服务器序列化，该服务器因实现更改而以不同顺序序列化字段。
  - 这两个`foo`和`bar`个别的消息，但不同的顺序串联。



# 源码剖析



## 序列化

ProtoBuf的最常见的使用流程是用.proto文件定义消息，然后在代码中对各个字段赋值，最后调用序列化函数进行编码，如下所示：

```c++
Example1 example1;
example1.set_int32val(val);
example1.set_stringval("hello,world");
example1.SerializeToString(&output);
```

这里，我们要关心的就是函数`SerializeToString`的实现。
