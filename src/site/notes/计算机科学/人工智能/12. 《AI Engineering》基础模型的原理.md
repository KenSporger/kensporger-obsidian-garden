# 训练数据

AI模型的表现取决于其训练数据的质量。使用像Common Crawl这种大型开源数据集（据说包含了大量政治宣传、阴谋论、种族主义、厌女言论），而非符合特定需求的专业数据可能导致模型在训练数据覆盖的任务上表现良好，但未必能在关注的专业任务上表现出色。

我们既可以从零开始训练特定语言或领域的基础模型，也可以在通用模型的基础上进行[[计算机科学/人工智能/11. 《AI Engineering》基础模型与AI工程#^3caba8\|微调]] 。而直接利用所有可用的数据（包括通用数据和专业数据）训练模型，需要投入更多的计算资源，却未必总能带来性能提升。

同一个模型在不同的国家语言上的推理能力上有所不同。主要是因为：
+ 数据集包含的各国语言数据量和代表性差异（通常英语数据量占比更大，因此表现也更好）；
+ 语言的结构及其所体现的文化差异也可能增加模型学习该语言的难度；
+ 某些语言的分词效率远低于其他语言，导致处理速度更慢且成本更高；

为了解决这一问题，许多模型专门针对非英语语言进行了训练。


## 特定领域

领域特定模型在生物医学领域尤其常见，例如DeepMind的AlphaFold，它使用了大约10万个已知蛋白质的序列和三维结构进行训练。基于建筑草图训练的模型可能会比Stable Diffusion更好地辅助建筑师，而基于工厂规划图训练的模型可能比ChatGPT这样的通用模型更适合优化制造流程。

# 建模

## 模型架构

当前的大模型均采用 **Decoder-only** 的 **Transformer** 变体架构。虽然也出现了 SSM、Mamba 等潜在替代架构，但尚未出现能全面颠覆、替代 Transformer 的新架构。

Transformer架构的优点：
+ **并行计算**：Transformer 的自注意力机制可对输入序列的所有 token 进行并行计算，解决了传统 RNN/LSTM 等序列模型必须按 token 顺序串行计算的缺陷；
+ **通用性与可扩展性**：原生 Transformer 采用 Encoder-Decoder 的通用框架，可灵活适配全场景任务：Encoder-only 结构适配文本理解、分类任务；Decoder-only 结构适配文本生成、对话等核心大模型场景；Encoder-Decoder 结构适配翻译、摘要等 seq2seq 任务。同时，该架构可无缝扩展至多模态领域。
+ **完善的工具链与工程生态**：目前Transformer 架构已形成极其完善的训练、推理、优化全链路工具链生态，包括注意力加速、量化、蒸馏、剪枝等。
+ **强大的语义建模能力**：自注意力机制可精准建模自然语言的语法、语义、逻辑关联，并衍生出上下文学习、思维链、工具调用等高级能力。

核心缺点：
+ **平方级计算复杂度**：当上下文窗口扩展到数十万 token 时，原生 Transformer 的计算量与显存占用会爆炸式增长；极高的参数量与计算量导致端侧设备很难部署高性能的原生大模型，推理的延迟也会较高。
+ **长上下文瓶颈**：超长序列下自注意力会出现 “注意力稀释” 问题，导致理解和生成能力下降。
+ **可解释性极差**：Transformer 的决策过程是黑箱模式，在强监管、高风险场景有合规与安全风险。
+ **训练成本高**：依赖海量的高质量训练语料与极高的算力投入，数据利用效率偏低。
+ **自回归的幻觉问题**：Decoder-only 架构下，生成过程中出现的事实错误、逻辑偏差会随着生成步骤逐级放大，进一步加剧了模型的幻觉问题。


## 模型规模

衡量模型规模的三个关键指标：
+ **参数量**：代表模型的学习能力。
+ **训练token数**：代表模型学习到的知识量。
+ **FLOPs**：代表训练成本。

### 参数量

**参数量**可以帮助我们估算训练和运行模型所需的计算资源。例如，一个模型拥有70亿个参数，如果每个参数使用2字节（16位）存储，那么推理时GPU所需的内存至少为140亿字节（14 GB）。

**稀疏模型**将参数分成不同的组，每一组被称为一个专家。在处理每个token时，仅有部分专家处于激活状态（被使用，其他专家参数置为0）。例如，Mixtral 8x7B，有8个专家，每个专家70亿参数，总共467亿个参数（有些专家共享了参数）；针对每个token，仅有两个专家处于激活状态，这意味起计算成本和推理速度与一个129亿参数的模型相当。

### 训练token数

在讨论模型规模时，必须考虑训练**数据的规模**，因为大模型需要与之规模匹配的数据集作为训练。一般用token数来衡量数据集的大小。截止2026年，LLM的训练数据集规模已达到万亿token级别，相当于几亿本书。

### FLOPs

模型的计算需求用是**FLOP**（floating point operation，浮点运算次数）进行衡量，而GPU等硬件性能用FLOP/s（每秒浮点运算次数）衡量。假设seed2.0需要使用$3.2×10^{25}$FLOPs，NVIDIA H300 单卡算力为$7.88×10^{14}$FLOP/s，采用1万张显卡，需要约 47 天才能训练完成。如果按云服务提供商提供的9 元/卡/小时（3年大客户6折），对应基础算力总费用超 1 亿元。
