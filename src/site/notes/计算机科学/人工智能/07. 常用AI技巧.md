# Prompt

## 项目Idea评估

```
请从以下维度评估这个项目：
1. 抱怨程度：用户的痛点有多深刻？
2. 发生频率：这个痛点的发生频次有多高？
3. 急迫原因：为什么现在、立刻、必须解决？
4. 是否稀缺：现有的解决方案是否匮乏或代价极其高昂
5. 购买的必然理由：是否存在真正未满足的需求，是否提供了绝对高效的解决方案，是否显著优于现有方案
6. 市场容量：当前可触达的市场规模，未来预期的增长曲线有多陡峭？
7. 经济可行性：价值与成本的利润率空间，目标用户的真实支付能力，产品的长期用户黏性
8. 实施障碍：产品开发难度是否过高，销售和分销渠道能否打通？早起筹备资金面临多少压力？
9. 获利周期：产品开发到准备就绪的时长，市场教育与接纳的准备时长，真实的销售周期多久
10. 外部风险：现在及潜在的竞争威胁，对第三方平台或供应链的危害，目标人群的接受壁垒
每一个维度，满分10分，分数越高，代表这个维度产品表现越好，成功可能性越大。根据网上资料进行调研再打分，给出分数总和（满分100），同时给出三四句总结关键评价。
```

## PPT大纲制作

```
# PPT主题：
## 背景介绍
- 作者： 
- 语言：
- 你的任务目标：帮助用户快速制作高质量PPT，提供设计建议、结构优化和内容排版等服务。

## 任务内容
- 设计PPT模板和幻灯片布局；
- 优化内容结构，确保逻辑清晰、层次分明；
- 提供视觉设计建议，包括色彩搭配和图表选择；
- 快速生成PPT初稿并根据反馈进行调整。
   
## 规则
- 设计风格需符合用户的核心主题和目标受众；
- 每张幻灯片的内容要一致且重点突出；
- 图文结合，使用合适的配图和图表来支持文本；
- 保持整体视觉一致性，遵循设计美学；
- 页数与时长的对应关系为1分钟大约1到2页，避免太长或太短；
- 讲稿字数与时长的对应关系为每分钟大约150到200字。
  
## 工作流程
- 欢迎阶段：热情欢迎用户，并介绍自己的角色和能力。
- 准备阶段：询问PPT主题、受众、目标、场合（均为必填），时长和页数要求（可选）；反复检查必填项是否齐全，确认收集完整后，将所有背景信息整理发送给用户确认，确认无误才进入下一步。
- 大纲阶段：根据背景信息推荐合适的页数，从信息型、说服型、故事型中选择最合适的表达框架（信息型采用Intro-Body-End结构，说服型用SCQS模型，故事型用英雄之旅模型），撰写详细大纲，并循环检查大纲是否满足所有规则，不满足则继续优化，最后将页数、框架和大纲内容发给用户确认，确认后才能进入讲稿阶段。
- 讲稿阶段：从第一页开始逐页撰写讲稿，每页完成后检查是否符合规则（特别是字数与时长对应），并将该页讲稿发给用户确认，确认通过再写下一页，如此循环直到所有页面讲稿完成。
- 整合阶段：将全部页面的讲稿合并为完整文稿，整体检查逻辑一致性、规则符合度，最后将整合内容提交用户确认，确认后即可交付。
```

AI工作流指在从0到1开发一个产品的过程中如何与AI进行协作的理念和流程。

### 1. 调研方案

不是一句话就让AI帮我实现一个功能，而是先调研：
+ 有没有现有的开源项目可用；
+ 可以选用什么技术，和其他技术的优劣是什么；
+ 根据前人经验，可能会踩什么样的坑，有什么技术风险；
+ 用户的真正痛点是什么；

调研是为了给自己和AI补充上下文，先判断调研深度，再选择调研场景。

|调研深度|适合场景|执行方式|
|---|---|---|
|L1 快查|确认一个工具、参数、链接或事实|主线程快速确认|
|L2 标准调研|技术选型、方案对比、GitHub 搜索、最佳实践|一个 Researcher 子代理|
|L3 深度调研|高风险决策、多方向对比、跨领域研究|多个 Researcher 并行|

| 调研场景    | 典型问题              |
| ------- | ----------------- |
| W1 方案发现 | 有没有现成工具、开源项目或竞品？  |
| W2 用户洞察 | 用户真正抱怨什么？痛点是什么？   |
| W3 技术评估 | 能不能实现？怎么复用？风险在哪里？ |
| W4 最佳实践 | 行业内成熟做法是什么？       |
| W5 知识扩展 | 最近有什么新技术、新工具、新动态？ |
| W6 文献研究 | 学术证据和理论基础是什么？     |
推荐下载链接：
- [Research Workflow Skill](https://github.com/wangjialiang678/research-workflow-skill)

### 3. 需求澄清

如何将自己的需求以正确的方式描述给AI，这涉及到需求澄清，需求澄清工作流的目标是：当你只有一句模糊 idea 时，AI 不要立刻进入技术实现，而是先追问：
- 用户是谁？
- 场景是什么？
- 痛点是真痛点，还是只是一个有趣想法？
- 什么是必须做，什么可以不做？
- 怎么判断这个功能真的完成了？
- 有没有现成工具可以复用？
推荐的Skill：[Requirement Discovery Skill](https://github.com/wangjialiang678/requirement-discovery-skill)

当需求已经清楚，下一步不是直接写代码，而是让AI输出一份PRD，其中包含测试验收标准。

### 4.AutoDev

有了PRD后，AI将按照以下的流程进行工作：
1. 读取 PRD。
2. 拆分任务。
3. 并行开发。
4. 合并代码。
5. 跑 P0/P1 测试。
6. 失败后自动修复，再验证。
推荐链接：[Auto-Dev](https://github.com/wangjialiang678/claude-auto-dev)


### 5. 前端设计

AI 做前端常见问题是：功能有了，但界面像模板，缺少真实产品气质。前端设计的目标是：让别人一眼看懂、愿意尝试、能顺利完成操作。
