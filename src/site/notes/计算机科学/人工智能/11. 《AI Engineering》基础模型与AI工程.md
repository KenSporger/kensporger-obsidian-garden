Chip Huyen《AI Engineering：Building Applications with Foundation Models》第一章。

**大模型**（large model），或称**基础模型**，是**大语言模型**（LLM）和**多模态大模型**（LMM）的统称。

# 语言模型

大语言模型最初只是普通的**语言模型**，该模型根据统计信息来和特定上下文中依据概率推断出下一个词。最早的语言模型可以追溯到20世纪50年代。

## token

语言模型的基本单位是token，根据语言的不同，一个token可以是一个字符、一个词或者一个单词的一部分，将原始文本拆分成token的过程称为**分词**（tokenization）。

![1773c1e0df555cf87f85ea5a8234687a_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E4%BA%BA%E5%B7%A5%E6%99%BA%E8%83%BD/assets/10.%20%E3%80%8AAI%20Engineering%E3%80%8B%E7%9F%A5%E8%AF%86%E6%A1%86%E6%9E%B6/1773c1e0df555cf87f85ea5a8234687a_MD5.png)

对于GPT-4，100个token大约相当于75个单词，模型能够处理的所有token的集合称为模型的**词表**（vocabulary），类似于词元字典or字母表，GPT-4的词表大小为100,256个token。分词方法和词表大小由模型开发者决定。

为什么语言模型以token，而不是单词或字符为单位？主要有三个原因：
+ token比字符有意义；
+ token数比单词少，减小了模型的词表；
+ token能处理未知单词；
例如cooking可以拆分为cook和ing两个token，都携带了原单词的一些含义。一个虚构的单词chatgpting，可以用chatgpt和ing两个token组成，帮助模型理解其结构。

## 自监督学习

在众多的ML算法中（如目标检测、推荐系统等），语言模型能脱颖而出成为规模化的核心，在于其采用了**自监督学习**。相比于**监督学习**，自监督学习突破数据标注的瓶颈，可以直接从输入数据中自行推断标签，使得训练数据的获取成本极大降低。

语言模型是怎么做到自监督的？每条数据序列同时提供了标签和用于预测这些标签的上下文，例如，句子“I love street food.”可以产生6个训练样本。

![6cca6c510481235a13667a557e51b8a7_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E4%BA%BA%E5%B7%A5%E6%99%BA%E8%83%BD/assets/10.%20%E3%80%8AAI%20Engineering%E3%80%8B%E7%9F%A5%E8%AF%86%E6%A1%86%E6%9E%B6/6cca6c510481235a13667a557e51b8a7_MD5.png)

自监督学习不同于**无监督学习**。在自监督学习中，标签是从输入数据中推断出来的；而在无监督学习中，则根本不需要标签。

> [!NOTE] 反思
> 在深度学习、神经网络流程的21世纪10年代，能够看清自监督是未来方向而选择NLP研究的该是多么地智慧！

## 模型参数

通常，模型的大小以其参数（parameter）量来衡量。一般来说，模型参数越多，其学习指定行为的能力就越强。

2018年OpenAI发布的首个GPT（generative pre-trained transformer，生成式预训练Transformer）模型，拥有1.17亿个参数；到了2019年GPT-2拥有15亿个参数；而2025年模型参数达到千亿级才称得上大模型。

更大的模型拥有更强的学习能力，同时也需要更多的训练数据来最大化其性能。用小数据集训练较大模型有时候效果可能还不如用小模型来得好。

# 基础模型

## 多模态大模型

语言模型的能力仅限于文本，而**多模态大模型**（large multimodal model，LMM）能够处理多种数据模态，包括图像、文本、视频、3D资源、蛋白质结构等。
![7871862adcf255c3760934b50c3d5ea5_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E4%BA%BA%E5%B7%A5%E6%99%BA%E8%83%BD/assets/11.%20%E3%80%8AAI%20Engineering%E3%80%8B%E5%9F%BA%E7%A1%80%E6%A8%A1%E5%9E%8B%E4%B8%8EAI%E5%B7%A5%E7%A8%8B/7871862adcf255c3760934b50c3d5ea5_MD5.png)

自监督学习同样适用于多模态模型。OpenAI使用了一种称为**自然语言监督**的自监督学习，在互联网上寻找同时出现的（图像，文本）对，构建了一个包含4亿个（图像，文本）对的数据集，且无人工标注成本。

## 通用模型

![7c8aab05ef23f1de9c6847f708a02417_MD5.png|Super-NaturalInstructions基准中的任务范围](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E4%BA%BA%E5%B7%A5%E6%99%BA%E8%83%BD/assets/11.%20%E3%80%8AAI%20Engineering%E3%80%8B%E5%9F%BA%E7%A1%80%E6%A8%A1%E5%9E%8B%E4%B8%8EAI%E5%B7%A5%E7%A8%8B/7c8aab05ef23f1de9c6847f708a02417_MD5.png)

基础模型也标志着从特定任务模型向**通用模型**的转变。通用模型在未经调整的情况下，就能较好地完成许多任务。不过，通常可以对通用模型进行**微调**，使其在特定任务上的表现最优。

假设一家零售商想构建一个为其网站生成产品描述的AI应用。一个开箱即用的模型或许能够生成准确的描述，但可能无法体现品牌的调性，生成的营销话术可能让人感觉流于空泛。
{ #3caba8}


此时可以使用三种技术来引导模型更好地生成想要的内容：
+ **提示工程**：精心设计详细的指令，并提供理想的产品描述示例；
+ **检索增强生成（RAG）**：将模型连接到客户评论数据库，让模型利用这些信息生成更好的描述；
+ **微调**：在高质量的产品描述数据集上对模型进行进一步训练；

将现有的通用模型适配到自己的业务上，通常比从零开始构建一个模型花费更少的时间和数据样本；当然针对业务特定场景构建的模型也有规模小、更快、更便宜的优势。


# AI工程

## 现状

**AI工程**是指在基础模型之上构建应用的过程。它成为了一个新兴学科，得益于三个理想条件：
+ **通用AI能力的增强**：AI可以被用于撰写电子邮件、回复客户请求、解释复杂合同、快速生成定制的高质量图片和视频，制作营销材料，编辑专业头像，将艺术概念可视化，为书籍绘制插图，合成训练数据、开发算法和编写代码等等。
+ **AI投资的增加**：随着AI应用的构建成本降低、上市速度加快，AI的投资回报变得更具吸引力。企业纷纷加速将AI整合到自己的产品和流程中。2025年，全球在AI领域的投资达到了千亿美元。
+ **构建AI应用的门槛降低**：模型通过API对外提供服务，接收用户请求并返回模型输出；AI可以让没有软件工程背景的人也能快速将想法转化为代码。

4个开源AI工程工具（AutoGPT、Stable Diffusion web UI、LangChain、Ollama）在GitHub上的星标数（star）已超过了比特币项目，并有望超越包括React和Vue在内的最受欢迎的Web开发框架。

## 技术栈

任何AI应用的工程技术栈都包含三层：应用开发层、模型开发层和基础设施层。在占比和增速上，应用开发最为显著，其次是模型开发、基础设施。

### 基础设施

基础设施包括一系列用于模型服务、数据和计算管理以及监控的工具。

### 模型开发

主要包含三个职责：
+ **建模与训练**：设计模型架构、训练模型并对其进行微调的过程，会用到TensorFlow、PyTorch等工具，需要具备专业的ML算法知识（神经网络架构、梯度下降等等）。
+ **数据集工程**：数据集工程是指为训练和适配AI模型而进行的数据收集、生成和标注工作。
+ **推理优化**：让模型运行得更快、更经济，常用方法如量化、蒸馏和并行化。基础模型的一个挑战是它们通常是自回归的，即逐个生成token。如果模型生成一个token需要10毫秒，那么生成100个token就需要1秒，随着基础模型的扩大，推理成本和延迟也越来越大，推理优化变得越来越重要。
![a505703718146c54404e78db968594be_MD5.png](/img/user/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%A7%91%E5%AD%A6/%E4%BA%BA%E5%B7%A5%E6%99%BA%E8%83%BD/assets/11.%20%E3%80%8AAI%20Engineering%E3%80%8B%E5%9F%BA%E7%A1%80%E6%A8%A1%E5%9E%8B%E4%B8%8EAI%E5%B7%A5%E7%A8%8B/a505703718146c54404e78db968594be_MD5.png)

### 应用开发

应用开发层包括以下职责
+ **评估**：选择模型、对进展进行基准测试、确定应用是否准备好部署，以及在生产环境中发现问题和改进空间。
+ **提示工程**：仅通过输入提示词来引导AI模型表现出期望的行为，而无须改变模型权重。不仅仅是告诉模型做什么，还包括为模型提供完成特定任务所需的上下文和工具（如记忆管理系统）。
+ **AI界面**：为终端用户创建的与AI应用交互的界面，通常是嵌入到各种产品中。例如独立的网页、桌面和移动应用；浏览器扩展；集成到聊天应用中的聊天机器人；AI界面也可以是语音形式（如语音助手）或具身形式。


> [!NOTE] 个人的职业选择
> 个人认为模型开发可以作为专门的研发岗位，而**应用开发通常只是岗位的一部分技能要求**而已，也是目前后端、客户端工程师需要学习的新技能，以便更好地将AI嵌入到原本的业务中去。而对于AI工程师而言，随着基础模型的出现，也需要更加深入地参与产品的构建过程（现有产品，再有模型）。

# 其它概念

+ **模型即服务**（（model as a service，MaaS）：由于训练大模型需要大量的资源，因此促使由少数组织开发的模型以服务的形式提供给人们使用。
+ **传统ML**（Machine Learning）：指所有基础模型之前的ML。
+ **训练**：通常作为一个统称，涵盖预训练（pre-training）、微调（finetuning）和后训练（post-training）。
+ **预训练**：指从头开始训练一个模型，其权重通常是随机初始化的。
+ **微调**：在已经训练好的模型的基础上继续训练，模型权重继承自之前的训练过程。
+ **后训练**：后训练和微调基本是等同的。模型开发者进行的训练通常称为后训练。例如，OpenAI可能会在模型发布之前进行后训练，以使其更好地遵循指令。应用开发者进行的训练则称为微调。
