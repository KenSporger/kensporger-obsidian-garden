## 硬件接口

![[计算机科学/操作系统/assets/06. 操作系统-设备管理/a59f0bef2d024254302084a426c4f0a3_MD5.png\|计算机科学/操作系统/assets/06. 操作系统-设备管理/a59f0bef2d024254302084a426c4f0a3_MD5.png]]

一个标准的I/O设备包含两个部分：接口和内部结构。硬件接口的本质就是寄存器，通常分为：

+ 状态寄存器：可以读取并查看设备的当前状态；
+ 命令寄存器：用于通知设备执行某个具体任务；
+ 数据寄存器：将数据传给设备或从设备接受数据；



## 数据传送方式
{ #8ddeaf}


+ 轮询方式；
+ 中断方式：
  + 当设备完成了自身操作，会抛出一个硬件中断，引发CPU跳转到中断服务程序处；
  + 中断不适合高速设备，会使系统频繁中断（中断有额外开销）；
  + 中断也不适合于网络。网络端收到大量数据包，如果每一个包都发生一次中断，那么有可能导致操作系统发生活锁，即不断处理中断而无法处理用户层的请求。
  + 如果设备速度时快时慢可以采用混合策略，先尝试轮询一小段时间，若设备没有完成操作，此时再使用中断；
  + 另一个优化是合并。设备在抛出中断前往往会等待一小段时间，再次期间，当有其他中断请求到来时，可以将这些多个中断合并成一次中断抛出；
+ DMA方式：中断方式中CPU的主要开销在于内存和设备数据寄存器间的数据拷贝，DMA方式能够省去这些开销，操作系统只要告诉DMA数据存放的内存位置、要拷贝的大小以及设备地址即可。



## 驱动程序

每个设备都有非常具体的接口，而我们希望操作系统尽可能的通用，例如文件系统，如何保证文件系统可以工作在SCSI硬盘、IDE硬盘、USB等不同设备之上？这个问题可以通过抽象技术来解决，在操作系统底层，是一些设备驱动程序，封装了各种设备交互的细节，并且提供具体的接口；在其之上是一个通用块层，用于将接口抽象化，使得文件系统不依赖于具体的硬件设备。

![[计算机科学/操作系统/assets/06. 操作系统-设备管理/d6658f643ed681801d8bd1062a315d35_MD5.png\|计算机科学/操作系统/assets/06. 操作系统-设备管理/d6658f643ed681801d8bd1062a315d35_MD5.png]]

当然，这种封装带来的结果就是尽管有一个设备可以提供很多特殊的功能，但为了兼容大多数操作系统它不得不提供一个通用的接口，这就是得自身的特殊功能无法使用。例如在使用SCSI设备的Linux中，SCSI设备提供非常丰富的报告错误，但其他的块设备只提供非常简单的报错处理，这样上层的所有软件只能在出错时收到一个通用的EIO错误码，SCSI提供的附加错误信息都不能报告给文件系统。

驱动程序是可以后期插入和移除的，有趣的是，通常操作系统的大部分代码都是各种驱动程序，比如Linux的驱动程序占比就超过了70%。当然，安装的驱动程序默认都不是激活状态。



## 磁盘驱动器



### 磁盘结构

![[计算机科学/操作系统/assets/06. 操作系统-设备管理/cbe6095fc97acb7f07d6f99083ad0e91_MD5.png\|计算机科学/操作系统/assets/06. 操作系统-设备管理/cbe6095fc97acb7f07d6f99083ad0e91_MD5.png]]

一个磁盘由多个**盘面**通过**主轴**串叠而成。一个盘面的结构如上图所示，每个同心环都是一个**磁道**，按照固定角度等分成多个**扇区**，一个扇区通常是512字节。磁盘会以一定速度逆时针旋转，**磁头**负责读写经过的扇区。此外为了能够读取不同磁道的扇区，磁头还可以移动，即**寻道**。

图中的一个盘面共有36个扇区，并且外圈磁道和内圈磁道的扇区数量一样，这是旧式磁盘的记录方式；在新式磁盘中，考虑到外圈磁道面积较大，会安排比内圈更多的扇区数量，在这样的方式下，外圈的读取速度要高于内圈，这是因为外圈的线速度较大，可以经过更多扇区。

为了支持顺序读写，扇区往往会设计成下图所示的偏斜样式。比如一次读取扇区11和扇区12，假设扇区没有偏移，那么读完扇区11后，只有一个扇区宽度时间用来寻道到内圈，如果磁头移动速度较慢，就会错过扇区12，从而等上整整一圈。

### 调度方案

读写一个磁盘块的时间花费主要有三部分：寻道时间、旋转时间、传输时间，其中寻道和旋转是最为昂贵的操作，例如一个磁盘传输时间一般只在十几微妙，但是寻道和旋转都在毫秒级别。因此调度算法的目的就是尽量减少不必要的寻道和旋转。

+ **最短寻道时间优先（SSTF, Shortest Seek Time First）**：优先处理与当前磁头最近磁道上的请求。主要的问题是在于较远磁道上的请求会饿死，即调度是不公平的。

![[计算机科学/操作系统/assets/06. 操作系统-设备管理/afd7416648fdf34e119e7496ed0cff83_MD5.png\|计算机科学/操作系统/assets/06. 操作系统-设备管理/afd7416648fdf34e119e7496ed0cff83_MD5.png]]

+ **电梯算法（SCAN）**：电梯算法和实际电梯的运行类似，总是按一个方向来进行磁盘调度，直到该方向上没有请求，然后改变调度方向。电梯算法是公平的，不会导致饥饿问题。

![[计算机科学/操作系统/assets/06. 操作系统-设备管理/729884dd8c7d0dc33645eed4db9d9942_MD5.png\|计算机科学/操作系统/assets/06. 操作系统-设备管理/729884dd8c7d0dc33645eed4db9d9942_MD5.png]]

+ **最短定位时间优先（SPTF,Shortest Positioning Time First）**：SSTF和电梯算法是仅针对寻道时间做出的调度优化，SPTF算法则综合考虑了旋转成本。例如下图，有扇区8和扇区16两个请求，那么应当先调度哪个？答案是视情况而定，当旋转时间远大于寻道时间时，先处理扇区8更好，反之寻道成本更大时，先处理扇区16更好。

![[计算机科学/操作系统/assets/06. 操作系统-设备管理/fcc3bb7f6ccb67283eb6e9f4271769d7_MD5.png\|计算机科学/操作系统/assets/06. 操作系统-设备管理/fcc3bb7f6ccb67283eb6e9f4271769d7_MD5.png]]

在现代系统上，除了操作系统会负责磁盘的调度以外，磁盘设备本身也具有复杂的内部调度程序，比如SPTF算法，该算法本身不适合在操作系统上运作，因为操作系统不知道磁道的边界和磁头的当前位置。

磁盘调度程序的另一个重要任务是I/O合并，即可以将一些列扇区较连续的多个单块请求合并为一个读写请求（顺序读要比随机IO快很多倍），能够有效的降低开销。
