# 流程

+ 从相机读取的是YUV、BGR8 原始数据，体积极大，必须编码压缩才能网络传输（本地进程传输的话直接用原始数据就行）；
+ 主流编码：H.264、H.265。264压缩算法：
  时间上压缩
	+ I 帧：关键帧，完整画面
	+ P 帧：预测帧，参考前面的I帧、P帧作差值压缩
	+ B 帧：利用前后帧做差值压缩，压缩率最高，但机器人 / 实时遥操作**基本不用 B 帧**，因为要等后面的帧，会增加延迟，不符合低时延要求。
  空间上压缩（图片压缩法）：
	+ 对单帧画面分块（16×16 像素），然后做帧内预测，压缩相邻相似像素。
+ 可以使用ffmpeg库、opencv库`VideoWriter`对YUV数据做编码；
+ 如果视频流实时传输，可以通过ros2的topic进行发布，或者使用zenoh作为ROS2的底层中间件；
+ 如果是浏览器前端直播，而且数据也不涉及安全，那就走公网用声网sdk；
+ 如果是整个视频传输，那就用阿里云oss；

# 遥操拓扑

操控前端 → 服务网关 → Zenoh/MQTT → 机器人
机器人 → Zenoh → 服务网关 → WebRTC → 操控前端

机器人端（端侧）：
+ 采集摄像头画面
+ H264编码
+ 发送实时视频流
后端：
+ 接受实时视频流，转为WebRTC/WebSocket推流
+ 鉴权、多路管理等等
前端/客户端：
+ 接收 WebRTC / WebSocket 视频流
+ 前端/客户端解码 H.264 实时渲染画面
