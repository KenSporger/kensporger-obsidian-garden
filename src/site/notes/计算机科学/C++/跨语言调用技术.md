# 概述

[《Linux下跨语言调用C++实践》](https://tech.meituan.com/2022/04/21/cross-language-call.html)一文讲述了跨语言调用动态链接库的技术——开发一次基于C++的so，通过不同语言的链接层封装成不同语言的组件库，并投入到对应的生成。其优点在于：

+ 主体的业务逻辑只需要在C++层开发一次并且持续迭代升级，封装层只需要极少量的代码，其它语言几乎不需要改动，只需要包含最新的动态链接库。
+ 使用C++实现主要业务，具备更高性能。

# 跨语言调用示例

Python、Java可以通过一些工具库来实现C接口的调用，但不支持调用C++接口。因此对于C++语言实现的接口，必须编写“胶水代码”转换为C语言实现（即在C++接口上层用C语言进行一次封装）。然后将C代码编译生成动态库，供Python、Java接口使用。整个流程如下图所示：

## C++代码

str_print.h

```cpp
#pragma once
#include <string>
class StrPrint {
 public:
    void print(const std::string& text);
};
```

str_print.cpp

```cpp
#include <iostream>
#include "str_print.h"
void StrPrint::print(const std::string& text) {
    std::cout << text << std::endl;
}
```

用以下命令编译生成静态和动态库。

```shell
## 静态库
g++ -fPIC -c str_print.cpp # 生成目标文件str_print.o
ar -rvs libstr_print_cpp.a str_print.o
## 动态库
g++ -shared -fPIC -o libstr_print_cpp.so str_print.cpp 
```



## Python调C++

通过`extern "C"`将C++代码封装为C代码：

c_wrapper.cpp

```cpp
#include "str_print.h"
extern "C" {
void str_print(const char* text) {
    StrPrint cpp_ins;
    std::string str = text;
    cpp_ins.print(str);
}
}
```

接下来需要编译生成`libstr_print.so`，方法有源码依赖、动态链接、静态链接三种方式。



### 编译方式对比

编写相关测试文件，模拟业务方调用场景。

c_wrapper.h

```cpp
void str_print(const char* text);
```

main.cpp

```cpp
#include "c_wrapper.h"

int main()
{
    str_print("hello");
}
```

#### 源码依赖

编译动态库：

```shell
g++ -shared -fPIC -o libstr_print.so c_wrapper.cpp str_print.cpp
```

业务方使用动态库：

```shell
g++ main.cpp -o demo -L . -lstr_print
```

运行：

```shell
export LD_LIBRARY_PATH=<动态库路径，如当前目录 .>
./demo
```

可见，源码依赖方式下业务方只需要依赖`libstr_print.so`，使用成本较小。但是动态库开发方需要获取到源码（str_print.cpp），对于一些现成的动态库，可能不适用。



#### 动态链接

编译动态库：

```shell
g++ -shared -fPIC -o libstr_print.so c_wrapper.cpp -L . -lstr_print_cpp
```

业务方使用动态库：

```shell
g++ main.cpp -o demo -L . -lstr_print -lstr_print_cpp
```

运行：

```shell
export LD_LIBRARY_PATH=<动态库路径，如当前目录 .>
./demo
```

采取动态链接方式编译生成的`libstr_print.so`，发布时需要携带上其依赖库`libstr_print_cpp.so`。 这种方式，业务方需要同时依赖两个so，使用的成本相对要高，但是不必提供原动态库的源码。



#### 静态链接

编译动态库：

```shell
g++ -shared -fPIC -o libstr_print.so c_wrapper.cpp libstr_print_cpp.a
```

业务方使用动态库：

```shell
g++ main.cpp -o demo -L . -lstr_print
```

运行：

```shell
export LD_LIBRARY_PATH=<动态库路径，如当前目录 .>
./demo
```

源码依赖方式下业务方只需要依赖`libstr_print.so`。动态库开发方不需要获得源码（str_print.cpp），但是要有相应静态库。



### 接入代码

Python标准库自带的ctypes可以实现加载C的动态库的功能。

str_print.py

```python
# -*- coding: utf-8 -*-
import ctypes
# 加载 C lib
lib = ctypes.cdll.LoadLibrary("./libstr_print.so")
# 接口参数类型映射
lib.str_print.argtypes = [ctypes.c_char_p]
lib.str_print.restype = None
# 调用接口
lib.str_print('Hello World')
```

LoadLibrary会返回一个指向动态库的实例，通过它可以在Python里直接调用该库中的函数。

```shell
python str_print.py
```





## Java调C++

Java调用C lib有JNI与JNA两种方式，从使用便捷性来看，更推荐JNA方式。

### JNI方式

Java从1.1版本开始支持JNI接口协议，用于实现Java语言调用C/C++动态库。JNI协议本身提供了适配层的接口定义，需要按照这个定义进行实现。



#### 声明本地方法

Java代码里，在需要跨语言调用的方法上，增加native关键字，用以声明这是一个本地方法。

JniDemo.java

```java
import java.lang.String;
public class JniDemo {
    public native void print(String text);
}
```



#### 生成头文件

通过javah命令，将代码中的native方法生成对应的C语言的头文件。这个头文件类似于c_wrapper作用。

```shell
javah JniDemo
```

得到的头文件大致如下：

```cpp
#include <jni.h>
#ifdef __cplusplus
extern "C" {
#endif
JNIEXPORT void JNICALL Java_JniDemo_print
  (JNIEnv *, jobject, jstring);
#ifdef __cplusplus
}
#endif
```

jni.h在JDK中提供，其中定义了Java与C语言调用所必需的相关实现。

JNIEXPORT和JNICALL是JNI中定义的两个宏，JNIEXPORT标识了支持在外部程序代码中调用该动态库中的方法，JNICALL定义了函数调用时参数的入栈出栈约定。

函数名的格式是固定的由`Java_{className}_{methodName}`构成，JNI会按照这个约定去注册Java方法与C函数的映射。

三个参数里，前两个是固定的。JNIEnv中封装了jni.h 里的一些工具方法，例如字符串转换函数等；jobject指向Java中的调用类，即JniDemo，通过它可以找到Java里class中的成员变量在C的堆栈中的拷贝。 jstring 指向传入参数 text，这是对于Java 中String类型的一个映射。



#### 编写函数实现

编写`Java_JniDemo_print`的实现。

```cpp
#include <string>
#include "JniDemo.h"
#include "str_print.h"
JNIEXPORT void JNICALL Java_JniDemo_print (JNIEnv *env, jobject obj, jstring text)
{
    char* str=(char*)env->GetStringUTFChars(text,JNI_FALSE);
    std::string tmp = str;
    StrPrint ins;
    ins.print(tmp);
}
```



#### 动态库链接

编译生成动态库。

```shell
g++ -shared -fPIC -o libJniDemo.so JniDemo.cpp str_print.cpp -I/opt/jdk1.8.0_301/include/ -I/opt/jdk1.8.0_301/include/linux
```

其中`/opt/jdk1.8.0_301`是通过命令行`echo $JAVA_HOME`得到的。

在JniDemo.java中增加加载动态库和测试的代码。

```java
import java.lang.String;
public class JniDemo {
    public native void print(String text);
    static {
        System.loadLibrary("JniDemo");
    }
    public static void main(String[] args){
        JniDemo demo = new JniDemo();
        demo.print("Hello World!");
    }
}
```

编译并运行。

```shell
javac JniDemo.java
java -Djava.library.path=<动态库路径，如当前目录 .> JniDemo
```







### JNA方式

JNI的实现方式本身的实现成本还是比较高的。尤其桥接层的C/C++代码的编写，在处理复杂类型的参数传递时，开发成本较大。为了优化这个过程，Sun公司推出了JNA(Java Native Access)工具。

JNA需要在Java项目中额外引入。使用时首先声明与动态库对应的Java接口类，然后加载动态链接库，并实现接口方法。

```java
package com.jna.demo;
import com.sun.jna.Library;
import com.sun.jna.Native;
public class JnaDemo {
    private CLibrary cLibrary;
    // 声明与动态库对应的Java接口类
    public interface CLibrary extends Library {
        void str_print(String text);
    }

    public JnaDemo() {
        // 加载动态链接库
        cLibrary = Native.load("str_print", CLibrary.class);
    }

    // 接口实现
    public void str_print(String text)
    {
        cLibrary.str_print(text);
    }
}
```

对比可以发现，相比于JNI，JNA不再需要指定native关键字，不再需要生成JNI部分C代码，也不再需要显示的做参数类型转化，极大地提高了调用动态库的效率。
