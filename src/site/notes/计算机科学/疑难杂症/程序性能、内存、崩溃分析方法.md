# Coredump

## 启用

Core dump是Linux基于信号实现的（就是各种signal）。Linux中信号是一种异步事件处理机制，每种信号都对应有默认的异常处理操作，默认操作包括忽略该信号（Ignore）、暂停进程（Stop）、终止进程（Terminate）、终止并产生core dump（Core）等。

生成时机：

1. 内存访问越界 （数组越界、字符串无\n结束符、字符串读写越界）
2. 多线程程序中使用了线程不安全的函数，如不可重入函数
3. 多线程读写的数据未加锁保护（临界区资源需要互斥访问）
4. 非法指针（如空指针异常或者非法地址访问）
5. 堆栈溢出

```
ulimit –c // 查看core dump机制是否使能, unlimited表示已经使能
cat /proc/sys/kernel/core_pattern // 查看dump默认生成目录， 如/usr/bin/core_helper %e %p %t

```


## gdb载入

使用GDB载入执行文件和核心转储文件进行调试。运行这个命令后，GDB会用核心转储文件初始化调试会话，这允许你检查程序崩溃时的状态（内存映像、寄存器状态、栈信息等）。
```
gdb ./program_binary core
```


## 函数调用栈

bt命令（backtrace的缩写）会显示导致程序崩溃的函数调用栈。

有时候`bt`没有显出正确的函数名有几种可能：
+ 可执行文件缺少调试符号，要用debug版本（strip前）的可执行文件；
+ 依赖的库文件缺少调试符号；
+ 优化过度，编译时使用`-O2`或`-O3`会导致这个问题；
+ 地址空间布局随机化（ASLR）；

## 局部变量

可用通过`info locals`查看某个函数内所有局部变量的值。

```
(gdb) core corefile # 加载崩溃转储文件 
(gdb) bt # 打印整个调用栈（看到所有帧） 
(gdb) frame 0 # 跳转到【崩溃发生的最顶层函数】 
(gdb) info locals # 查看这一层函数里的局部变量（找崩溃原因）
```


# valgrind

可以在程序运行时使用 valgrind 来检查内存泄漏问题，从而帮助在 coredump 分析时获得更多信息。

```
valgrind --leak-check=full ./your_program
```

# objdump/IDA

使用objdump命令或者IDA工具对程序进行反汇编。

```
objdump -d your_program > disassembly.txt
```

例如[[计算机科学/疑难杂症/链接三方库引起的异常无法正常捕获问题\|链接三方库引起的异常无法正常捕获问题]]就使用过IDA进行反汇编，去查看链接以后，异常捕获代码发生了什么改变。


还需要补充ThreadSanitizer、AddressSanitizer、pmap、memwatch等工具。

buffer overflow检查：静态工具（Clang Static Analyzer、Coverity）、动态检测工具（AddressSanitizer、Valgrind）

# Perf

对已在跑的进程采样，开销相对小，能看到火焰图、调用栈和热点函数，用于函数性能优化、函数阻塞分析。

## 安装

Linux上工具安装

```sh
sudo apt install linux-tools-common linux-tools-generic
```

如果是要分析Docker里的进程，有三种办法：
+ 直接在Docker里按上面命令进行安装；
+ 如果Docker里没法安装这个perf，可以在宿主机上执行Perf；
+ 如果宿主机不能直接装Perf（如macos没有这个工具），那可以通过Docker sidecar方式（让Cursur写Dockfile和run-perf-sidecar.sh脚本）

## 分析

执行下面的命令，采样结束后，数据写入 `perf.data`。

```sh
# -F 99: 以 99 Hz （99 Hz 是常见的非整数频率，可避免与某些周期性任务产生共振，从而获得更均匀的样本分布）的频率进行采样
# -g: **记录调用图（call graph）**。启用堆栈回溯（stack trace），使得 `perf report` 可以展示每个采样点对应的函数调用链（如 `main -> foo() -> bar()`），便于定位性能瓶颈所在路径。
# sleep 30: 采样持续时间为 **30 秒**
perf record -F 99 -g -p 960 -- sleep 30
```

### 火焰图
{ #73c1b8}


安装`FlameGraph`工具

```sh
git clone --depth=1 https://github.com/brendangregg/FlameGraph.git
brew install perl
```

导出perf原始采样数据

```sh
perf script -i perf.data &> ./perf.unfold
```

生成火焰图

```sh
./FlameGraph/stackcollapse-perf.pl ./perf.unfold &> /perf.folded
./FlameGraph/flamegraph.pl ./perf.folded > perf.svg
```
