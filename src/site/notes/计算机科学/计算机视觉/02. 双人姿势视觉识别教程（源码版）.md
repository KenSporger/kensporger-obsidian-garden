| 方案                       | 好不好上手     | 能识别多少个点  | 多人时稳不稳               | 反应快不快      | 最适合做什么             |
| ------------------------ | --------- | -------- | -------------------- | ---------- | ------------------ |
| MediaPipe PoseLandmarker | ⭐⭐⭐⭐⭐ 最简单 | 33个（最精细） | ⭐⭐⭐⭐ 还不错             | 较快，25～30帧  | 需要精细动作，如手势、面部表情等等  |

目前，MediaPipe PoseLandmarker 和 MoveNet MultiPose 已验证效果还不错，集成也相对容易，因此首推MediaPipe PoseLandmarker，其次是MoveNet MultiPose。



# MediaPipe PoseLandmarker方案

## 如何区分玩家 1 和玩家 2？

小明、小刚玩双人游戏时，MediaPipe 是无法确切知道哪个是小明、哪个是小刚的，它只返回最多 2 组独立的 33 个特征点。游戏侧用 空间位置 做映射。


Step1: 指定numPoses=2，让模型最多检测 2 人。

```JavaScript
async function createPoseLandmarker(visionTasks) {
    if (poseLandmarker?.close) poseLandmarker.close();
    poseLandmarker = await PoseLandmarkerClass.createFromOptions(visionTasks, {
        baseOptions: { modelAssetPath: MODEL_URL },
        runningMode: 'VIDEO',
        numPoses: 2, // 指定numPoses=2，让模型最多检测 2 人
        minPoseDetectionConfidence: 0.5,
        minPosePresenceConfidence: 0.5,
        minTrackingConfidence: 0.5
    });
```

Step2: 模型按髋部中心 X 从小到大排序（画面从左到右），也就是说屏幕左侧的为玩家1，右侧的为玩家2，不是靠人脸识别、衣服颜色或跨帧 ID 追踪来识别玩家的。

```JavaScript
function hipCenterX(landmarks) {
    return (landmarks[23].x + landmarks[24].x) / 2;
}
# sorted[0]是屏幕左侧的玩家，sorted[1]是屏幕右侧的玩家
const sorted = (results.landmarks ?? []).slice().sort((a, b) => hipCenterX(a) - hipCenterX(b));

for (let i = 0; i < 2; i++) {
    const landmarks = sorted[i] ?? null;
    const detected = !!landmarks;
    playerStates[i].detected = detected;
    const gesture = classifyGesture(landmarks, i);
```


## 画面里只有 1 人或 3 人会发生什么？

- 只有 1 人：MediaPipe 返回 1 组 `landmarks`，排序后：`sorted[0]` 有数据，`sorted[1]` 为 `null`。

- 有3人：MediaPipe 内部会选出它认为最可信的 2 人，第 3 人 完全被忽略，不会出现在 `results.landmarks` 里。

## 两人交换位置会发生什么？

因为 每帧都重新按 X 坐标排序分配，交换位置后控制权会 立即对调：

+ 交换前：左=A → 红方，右=B → 蓝方
+ 交换后：左=B → 红方，右=A → 蓝方

## 大人和小孩，动作判断有何差异？

由于大人、小孩的身高不同，对于半蹲等动作，在静止站立情况下先记录每个人自己的基准髋部高度，然后通过运动中的偏移量进行判断。
