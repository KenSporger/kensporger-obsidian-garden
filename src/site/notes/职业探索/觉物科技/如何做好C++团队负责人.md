目前觉物科技给我定了C++团队负责人的职级，遂写此文以做梳理，做好迎接新工作的准备。在机器人技术这块，自己还是个新手，而昔日在DJI的管理也说不上出色，在GAP半年多后空降到一个新的初创公司，要考虑和适应的事情非常多。

# 挑战与机遇

机遇、优势：
+ **发展空间大**：随着团队人数的增加，个人在公司中的影响力将逐步提升，有机会获得股票期权等激励；
+ **适合管理实践**：目前团队仅有3人，管理难度较低，非常适合结合学校所学理论进行实践探索，积累管理经验，并开展论文课题研究；
+ **有确定的退路**：通过该公司进入机器人领域，即使未来发展不顺，也能积累相关技术经验，便于跳槽至宇树、智元等类似企业；
+ **大公司与交大经历**：在DJI工作、交大读书的经历使自己在技术、业务和管理方面具备更广阔的视角，有助于快速适应新岗位。


挑战：
+ **新的组织环境**：作为[[职业探索/工程管理/10. 管理者的画像、特质与职责#^246722\|外聘]]负责人，从大公司转入陌生的小公司，需要适应新的组织流程和文化，建立良好的人际关系以获得人事基础；
+ **新的技术栈**：团队使用ROS2，而自己对此接触较少，初期可能在技术和业务上难以与团队成员同步；
+ **前景不确定**：对公司了解有限，无法判断担任负责人有多大风险，也无法准确评估公司的未来发展。

## 工作习惯

做到以下习惯：
+ **管理好自己的时间**：沿用在DJI的Notion任务面板；
{ #5e5847}

+ **每日/周复盘**：每天晚上花半小时对当日事项进行回顾，在OB中记录技术/人际/管理上的思考、复盘时间情况、做第二天事项；周末对整周工作进行回顾总结，以及规划下周事项。过去的经历表明，我并不擅长临场处理管理问题（特别是在繁重的工作压力之下），所以每天有半小时安静的时间用来思考复盘非常必要，最好是结合MEM的工程管理导论所学，用科学地方法进行实践。
+ **做好资料数据的留档**：每个需求/框架改良要有过程记录，在完成时要有一份需求报告（内容包括背景、时间线、产品/技术设计、质量情况、客户验证反馈等），并做到随时带离。
+ **正念、有担当**：做一个稳定、理性、勇敢的人，时刻保持冷静，敢于为下属担责（当然是自己认可的下属）；

## 技术建设

目前阶段，每天花至少1个小时进行个人的技术提升，主要做到：
+ 尽快地熟悉ROS2的基本用法；
+ 用Claud Code等AI工具提升开发、分析bug的效率；
长期来看，要定期推进[[尤里卡时刻/summary/2025 Summary#^a53ff3\|ROS小车项目]]学习。

对于团队技术建设，按如下步骤展开：
1. 快速初步了解团队的技术文档完善度、项目代码质量、成员技术水平、技术方案评审以及CR是否规范、现存bug、技术负债、AI工具使用；
2. 对成员的技术方案、代码PR进行review（**借此对成员做的需求功能要有了解**）；
3. 在学习项目代码中，主动发现并记录框架问题及改良方向；
4. 在编译、调试项目代码过程中，编写新人学习文档，为后续团队扩招奠基；
5. 提升研发人效，包括AI编码工具建设、自动化CI、CR、测试流程；

## 团队管理

计划入职当天请同组人聚个餐，完成对成员的初步了解：爱好、性格、工作经历、互相之间的氛围、对公司的看法等等，再做进一步地管理策略。

1. **需求与人力排期**：了解目前团队的需求管理方式，看有没有必要进行改进（飞书Excel需求池+文档周事项）。
2. **进度反馈与周会**：根据下属成熟度考虑通过什么样的形式来及时掌握成员需求进度、以及任务分配。
3. **不耻下问**：由于自己是半路加入，对以往的技术框架、需求缺乏了解，在这一块在前期要多请教组员。
4. **信息传达**：采用“Y”式沟通，涉及外部的重要事项、问题，最好都经过自己一道（比如别人咨询某个需求问题，我不了解但组员懂的时候），一定的控制能力是需要的，能维持自己的权威地位。
5. **评价与辅导**：对每个成员做的事情（需求等）都要有记录与评价，通过这个记录去发现他的长处，以及作为绩效考核的参考。
6. **团建活动**：保证至少每月一次的聚餐频次，如果生活上能一起玩那更好（比如邀请来交大听课hhh）。


## 眼观六路、耳听八方

在入职前期，和上级约定每天工作交流的时间，交流的内容包括：
+ 组织结构、各个领域的大哥；
+ 之后的业务规划；
+ 遇到的管理困难以及自己的解决思路（需要大哥给意见或者授权的）；
+ 大疆、交大的管理思路交流；

在需求对接、联调中，与产品经理、其他部门同事打好关系，并获取有关信息：
1. 产品：一些市场调研、销售情况、用户反馈、竞品信息等；
2. 部门同事：技术上的实现方式；
