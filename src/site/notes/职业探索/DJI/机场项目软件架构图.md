旧链路拓扑和云平台的所有通信都走mqtt协议。机场里进程通信使用tcp和dds，两者区别在于：

|      | TCP                                       | DDS                                               |
| ---- | ----------------------------------------- | ------------------------------------------------- |
| 使用场景 | 1. 和飞机之间所有v1数据指令交互<br>2. 和机场之间的所有v1数据指令交互 | 1. 物模型上报数据<br>2. 作业流程中和机场的控制交互（进入工作模式、起飞准备、降落准备等） |
| 数据格式 | v1协议，字节流                                  | json，格式化字符串                                       |
| 通信模型 | 一对一，需要dji_system路由转发，分发效率低                | 多对多，分发效率高                                         |
| 历史设计 | 手飞场景在遥控器上只有TCP协议                          | 机场特有                                              |

# 网联链路拓扑

[Open: 机场项目软件架构图-1774356118505.png](/img/user/%E8%81%8C%E4%B8%9A%E6%8E%A2%E7%B4%A2/DJI/assets/%E6%9C%BA%E5%9C%BA%E9%A1%B9%E7%9B%AE%E8%BD%AF%E4%BB%B6%E6%9E%B6%E6%9E%84%E5%9B%BE/56c44718543b6bc6ea7ffee7cceb86b9_MD5.jpg)
![职业探索/DJI/assets/机场项目软件架构图/56c44718543b6bc6ea7ffee7cceb86b9_MD5.jpg](/img/user/%E8%81%8C%E4%B8%9A%E6%8E%A2%E7%B4%A2/DJI/assets/%E6%9C%BA%E5%9C%BA%E9%A1%B9%E7%9B%AE%E8%BD%AF%E4%BB%B6%E6%9E%B6%E6%9E%84%E5%9B%BE/56c44718543b6bc6ea7ffee7cceb86b9_MD5.jpg)

指令实时链路（DRC）相比传统非实时业务链路的优势在于：云端与设备成功建立 MQTT 连接以后，将分配一个 EMQX Broker 专门用于云端到设备端的 DRC 通信链路，使得传输稳定、响应更快，而后者一个命令要经过好几个服务节点，要排队处理（尤其是MQ），延迟更大。

+ EMQX（Erlang MQTT Broker）：基于 Erlang 开发的 高并发 MQTT 消息服务器，作用有
	+ **MQTT 协议处理**：作为 MQTT 服务器，接收飞机设备的 MQTT 连接请求；
	+ **设备认证与权限控制**：验证设备身份，控制设备可订阅 / 发布的主题；
	+ **高并发连接管理**：支撑大量飞机设备的并发连接，保证消息的可靠投递与顺序性；
+ TAS（Thing Access Service）服务：设备接入与消息路由层，连接 MQ 消息队列与底层 EMQX 网关，作用有
	+ **设备接入管理**：与 EMQX 网关对接，管理飞机设备的连接、上下线状态、身份认证与权限校验。
	+ **消息转发**：将 MQ 中的云端下发消息转发给 EMQX，推送给设备；同时将 EMQX 上报的设备消息存入 MQ，供 Duplex 服务读取后推送给前端。
	+ **协议适配**：适配 CSDK3.0 协议与 MQTT 协议，完成云端与设备端的协议转换。
+ MQ（消息队列）：异步消息缓冲层，相当于socket发送的缓存区，主要实现异步非阻塞功能
	+ **异步解耦**：缓存 Duplex 服务下发的非实时指令和设备上报的非实时数据，避免服务端与设备端发送阻塞。
	+ **削峰填谷**：应对设备并发连接或消息突增场景，保证消息不丢失、不阻塞。
+ Duplex 服务：
	+ **会话管理**：维护与前端的 WebSocket 连接，管理用户会话与权限。
	+ **消息路由与协议转换**：将前端的非实时业务请求（CSDK3.0 协议）转换为 IOT 平台可识别的消息格式，转发给 IOT 平台的 MQ 消息队列；同时将 IOT 平台推送的设备数据回传给前端。
	+ **双工通信保障**：实现 “前端↔服务端↔设备” 的双向消息传递，保证非实时业务的可靠交互。

## [声网直播框架](https://docportal.shengwang.cn/cn/live-streaming-standard-legacy/start_live_standard_android?platform=Android)

[Open: 机场项目软件架构图-1774345923903.png](/img/user/%E8%81%8C%E4%B8%9A%E6%8E%A2%E7%B4%A2/DJI/assets/%E6%9C%BA%E5%9C%BA%E9%A1%B9%E7%9B%AE%E8%BD%AF%E4%BB%B6%E6%9E%B6%E6%9E%84%E5%9B%BE/776ae0a6a84c6b8229d7782f80d943a9_MD5.jpg)
![职业探索/DJI/assets/机场项目软件架构图/776ae0a6a84c6b8229d7782f80d943a9_MD5.jpg](/img/user/%E8%81%8C%E4%B8%9A%E6%8E%A2%E7%B4%A2/DJI/assets/%E6%9C%BA%E5%9C%BA%E9%A1%B9%E7%9B%AE%E8%BD%AF%E4%BB%B6%E6%9E%B6%E6%9E%84%E5%9B%BE/776ae0a6a84c6b8229d7782f80d943a9_MD5.jpg)

### 01. 角色设置

APP客户端集成了声网客户端SDK，可以调用`setClientRole`来设置主播or观众（推流、拉流、设置权限不同）。

### 02. token获取

这里服务器并不需要集成声网SDK。

APP主播向服务器请求token，服务器为主播生成一个UID作为身份标识，然后创建一个直播ID，生成一个Channel ID，再使用声网提供的AccessToken2（需要事前申请License）来生成token。

数据库存储：`{"直播ID": [UID、Channel ID、token]}`。

之后APP观众想要观看直播，也向服务器请求token，该请求会带上直播ID，服务器检索数据库，返回Channel ID，并给该观众分配一个新的UID、token。

声网的鉴权token因为包含了UID身份标识，因此主播和每个观众都不同。

### 3.加入频道

直播客户端拿到UID、Channel ID、token，后调用声网`joinChannel`创建并加入频道，声网SD-RTN会进行鉴权，由于主播和观众所持Channel ID相同，所以能进入同一个频道。

**SD-RTN** 全称是 **Software Defined Real-time Network**（软件定义实时网），是声网自研的**全球实时音视频传输骨干网**，也是声网所有实时服务的核心底层基础设施，负责**低延迟、高可靠**地分发、转发音视频流，让全球不同地区的客户端能实时互通。

### 4. 推流、拉流

APP主播端调用`pushVideoFrame`或者`setVideoSource`来进行推流（视频帧），APP观众端调用`setRemoteVideoRenderer`进行拉流渲染。


### 5. 结束直播

当所有人调用`leaveChannel`退出频道或被判定离线后，声网会自动回收频道资源，并且服务器端也会收到客户端的结束回调，并进行状态更新和资源回收。

## [Cloud API](https://developer.dji.com/doc/cloud-api-tutorial/cn/overview/product-architecture.html)

在设备上绑定MQTT网关地址和密码，即可使设备上线至三方平台。

![职业探索/DJI/assets/机场项目软件架构图/061c037ec19bfabd4484d4cc8f7b96b8_MD5.jpg](/img/user/%E8%81%8C%E4%B8%9A%E6%8E%A2%E7%B4%A2/DJI/assets/%E6%9C%BA%E5%9C%BA%E9%A1%B9%E7%9B%AE%E8%BD%AF%E4%BB%B6%E6%9E%B6%E6%9E%84%E5%9B%BE/061c037ec19bfabd4484d4cc8f7b96b8_MD5.jpg)

从架构分层上可以看出，上云API是基于大疆行业版无人机的基础上对外提供的接口，整体思路采用与物联网类似的端边云架构分层。此处要特别注意，无人机并不能直接接入第三方云平台，它需要先连接网关设备（遥控器、机场），然后通过遥控器中的DJI Pilot 2或者机场间接上云，DJI Pilot 2、大疆机场在注册登录第三方云平台时，会同时把飞机和负载的能力一起上报。

网关设备与第三方云平台之间的通信链路均采用业界通用的MQTT、HTTPS、Websocket协议，并在这个协议的基础上，抽象出的各个硬件设备的物模型以及业务应用所需的功能集。

第三方云平台泛指网关设备可以直接访问的各个服务端，对于上云API来说，只要通信链路能够访问到第三方云平台服务，即可进行通信，这样对于第三方云平台的环境部署就没有做限制，无论是私有化部署还是公有云部署，只要能访问均可工作。

第三方云平台需要先部署MQTT网关、HTTPS服务、Websocket服务、对象存储等基础服务，打通与网关设备的通信链路，即可进行功能集开发实现，上云API提供的功能集主要分2部分，一部分是基于DJI Pilot 2的，有飞手操作的场景，该场景下提供的功能集有：地图元素、态势感知、直播、媒体库、航线库、设备管理。另一部分是主要面向大疆机场的场景，功能集有：固件远程升级、设备异常告警、机场远程控制等等，当然，有些功能集是两种场景均有重叠的，例如视频直播，具体使用方式详见各个功能集方案及API说明章节。

第三方云平台在打通与无人机的业务之后，即可通过自身私有协议，搭建前端web页面、APP应用、小程序等，深入业务场景例如安防、能源、环保、海事等，构建一个完整的场景业务工作流。

2025年DJI暂停了对Cloud API转而使用OpenAPI的开放方式，主要原因为：
+ Cloud API主要是三方平台与设备之间的通信接口，而设备上报的属性非常原始（飞机经纬度、WPMZ版本号等）且复杂，三方难以理解。
+ 司空基于设备物模型开发的功能（如飞行记录），三方如果要用必须自己实现一遍，适配的成本极高。
+ 用户手上的设备有版本差异、机型差异，导致Cloud API在不同机型和设备版本上也会有差异。
