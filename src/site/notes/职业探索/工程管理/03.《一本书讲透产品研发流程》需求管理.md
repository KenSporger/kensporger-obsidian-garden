# 五个阶段

需求管理的五个阶段：收集、分析、分配、实现和验证。
和[[学术研究/论文笔记/论文09-A公司汽车智能座舱软件项目需求管理研究与实践#^900fb0\|需求管理的分析阶段]]对应关系如下：
+ 收集-内部/外部需求获取
+ 分析-分析（QFD、AHP）
+ 分配-无
+ 实现-需求定义、评估、跟踪、变更、测试
+ 验证-验证

## 需求收集

需求包括外部需求和内部需求。
其中外部需求可分为客户需求和市场需求，前者是某些客户的具体需求，后者为对行业、政策分析得出的共性需求。
实际应该以外部需求为主，兼顾内部需求。

在DJI中，需求主要来自于市场售后同事反馈的KOC/用户需求、项目/产品经理调研后为了进入某个领域或者某个客户群体而发现的需求、研发提效需求、国内国际法规的需求等等。

## 需求分析

需求分析的目的是进行过滤。可以用[[#^1385f1|$APPEALS]]、QFD、AHP等工具进行描述，过滤掉重复和无效的需求。在此基础上，分析需求的投入产出比、优先级等等。

这一步DJI通常由各个业务组的Leader和产品进行初步评估。

## 需求分配

在需求分析后，将需求分配到不同的项目、业务组中去。比如对于机场项目来说，有好几代，一个用户需要的需求，需要考虑是不是所有机型都要上，还是根据产品主打的市场和用户群体而只上其中一款机型。

## 需求实现

需求实现包含了定义、设计、开发、测试以及期间可能出现的需求变更，与[[职业探索/工程管理/01.《一本书讲透产品研发流程》概述#^76934d\|V模型]]的对应关系如下。

## 需求验证

需求验证和测试的区别是：验证是站在客户的角度，测试时站在研发的角度。

有些企业虽然有验证环节，但是验证的人员是研发人员，容易导致验证不充分；好的做法应该是由市场人员或运营人员依据原始需求，采用黑盒方式验证；也可以组织团队到客户处开展实验验证，完全模拟未来展品的真实应用场景。

# 常见问题

大部分企业在需求管理中存在以下问题。

## 收集随意

企业任何员工都可以通过正式或非正式手段收集需求，没有统一的收集入口。

这个在DJI的情况还好，因为每个需求都是跟着每个版本上的，而每个版本的需求都是由楚越和产品经理、各组负责人和FO一起审阅才能成为正式需求，部门对于打黑工、乱接需求的行为也是禁止的。

解决方案：
+ 规定销售、市场人员外出调研回来后按统一模板提交收集到的需求清单；
+ IT系统维护统一格式的需求池；
+ 在不同组织层级设立“需求管理员”（一般是兼职），作为统一入口；

## 传递偏差

客户需求->销售/市场人员->产品->研发，这个传递链上会有内容偏差。

这个在[[学术研究/MEM论文选题-需求管理#^4da2c7\|MEM论文选题-需求管理#^4da2c7]]中也有提及，但大多情况下由于由KOC验证环节，会在发布前被发现，然后引起需求变更。

所以要确认[[职业探索/DJI/FeatureOwner的自我修养#^6294da\|需求的来源]]，以及时发现和纠正偏差。

## 需求跟丢了/研发自行删减功能

有些需求或者功能到最后没实现。大多其实出现在研发头上，有几个原因：
+ 产品设计时候遗漏（比较少）；
+ 研发未充分理解产品文档（主要原因）；
+ 由于技术实现难度或者带宽问题，研发偷工减料（自己就曾有过233）；
+ [[学术研究/MEM论文选题-需求管理#^de8a88\|迁移换代时候需求列表不全]]；

## 运动员=裁判员

研发既当“运动员”，又当裁判员，自己开发的功能自己验收，导致需求验证不充分或者不够客观。

最好的方式是需求联调完后，让产品、市场或者需求提出者进行体验。


## 其他问题

+ 需求分析和分配存在问题；
+ 人员能力不足；
+ 组织分配不合适；
+ [[学术研究/MEM论文选题-需求管理#^42ae34\|MEM论文需求管理主要问题]]


# $APPEALS需求描述模型

$APPEALS模型是IBM公司用于需求分析的工具，将客户需求分成了8个维度。
{ #1385f1}

+ $（Price）：为产品愿意支付的价格；
+ A（Availability）：购买的便利性；
+ P（Packaging）：客户期望的设计、外观特征；
+ P（Performance）：客户期望的产品功能和性能；
+ E（Easy to use）：产品的易用性；
+ A（Assurance）：产品/服务的可靠、安全、售后等；
+ L（Life cycle of cost）：生命周期成本，如油费、保养；
+ S（Social acceptance）：社会接受程度，可以理解为口碑；

![03.《一本书讲透产品研发流程》需求管理-1772461014403.png](/img/user/%E8%81%8C%E4%B8%9A%E6%8E%A2%E7%B4%A2/%E5%B7%A5%E7%A8%8B%E7%AE%A1%E7%90%86/assets/03.%E3%80%8A%E4%B8%80%E6%9C%AC%E4%B9%A6%E8%AE%B2%E9%80%8F%E4%BA%A7%E5%93%81%E7%A0%94%E5%8F%91%E6%B5%81%E7%A8%8B%E3%80%8B%E9%9C%80%E6%B1%82%E7%AE%A1%E7%90%86/03.%E3%80%8A%E4%B8%80%E6%9C%AC%E4%B9%A6%E8%AE%B2%E9%80%8F%E4%BA%A7%E5%93%81%E7%A0%94%E5%8F%91%E6%B5%81%E7%A8%8B%E3%80%8B%E9%9C%80%E6%B1%82%E7%AE%A1%E7%90%86-1772461014403.png)


在模型的应用中，通常会给各个维度赋予权重，计算综合值。此外，该模型还可以结合雷达图用于分析产品、企业之间的竞争强弱关系。

![03.《一本书讲透产品研发流程》需求管理-1772461110825.png](/img/user/%E8%81%8C%E4%B8%9A%E6%8E%A2%E7%B4%A2/%E5%B7%A5%E7%A8%8B%E7%AE%A1%E7%90%86/assets/03.%E3%80%8A%E4%B8%80%E6%9C%AC%E4%B9%A6%E8%AE%B2%E9%80%8F%E4%BA%A7%E5%93%81%E7%A0%94%E5%8F%91%E6%B5%81%E7%A8%8B%E3%80%8B%E9%9C%80%E6%B1%82%E7%AE%A1%E7%90%86/03.%E3%80%8A%E4%B8%80%E6%9C%AC%E4%B9%A6%E8%AE%B2%E9%80%8F%E4%BA%A7%E5%93%81%E7%A0%94%E5%8F%91%E6%B5%81%E7%A8%8B%E3%80%8B%E9%9C%80%E6%B1%82%E7%AE%A1%E7%90%86-1772461110825.png)

在DJI中，这几个维度可能不一定适用，但是这样的思路可以借鉴，结合公司产品业务情况，制定合适的评价维度。
