# 架构定义：4R

软件架构包含了四个要素：
+ **顶层结构（Rank）**：架构是分层的，但也不是事无巨细的，要把握层级结构的度；
+ **组成角色（Role）**：各部分零件；
+ **角色关系（Relation）**：零件之间的接口；
+ **运作规则（Rule）**：角色之间如何协作来实现“1+1>2”的；

无论是自己绘制、讲解，还是看别人画的架构，都要关注这四个要素。**软件架构是动态变化的**。

## 现状

目前国内企业很少用4+1视图来描述架构，有几大原因：
+ 架构复杂度增加，4+1视图在1995年被提出时候大多是单体系统，现在都是分布式系统了。
+ 理解困难，4+1视图的逻辑视图、开发视图、处理视图容易混淆（很难给团队成员普及）。

# 系统序列图

系统序列图（System Sequence Diagram）用来描述架构设计里的规则（Rule），即4+1里的处理视图，用于描述一个功能/需求的流程，一般都用UML图来画。


# 总结

总体视频课程讲得比较一般，比较浅显，常见架构图画法和4+1实际上也没有太大区别。主要的几点收获：
+ 架构图有几种分类，主要看受众，比如给高p看处理架构就不太合适；面试时候应该用系统架构或者应用架构。
+ 要清晰、准确地运用形状、颜色、线条变化等区分元素的含义，避免混淆。
+ 多用分组、分层进行聚类、分级。
