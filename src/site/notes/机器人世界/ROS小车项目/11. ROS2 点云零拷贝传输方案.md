# ROS1 的大数据传输痛点

ROS1 默认 TCPROS 传输大消息（如点云、图像）存在三大痛点：
+ **多次内存拷贝**：发布者序列化->内核缓冲区->订阅者反序列化，至少三次拷贝；
+ **带宽瓶颈**：TCP 协议头开销大，大消息分段传输效率低；
+ **序列化开销**：ROS1使用的是自定义的一套二进制流序列化/反序列机制，该方案对对复杂数据结构（如图像/点云数据）效率不高。
基于ROS1的优化方案包括：使用UDPROS、使用第三方库实现共享内存等。


> [!NOTE] ROS原生序列化 VS Protobuf
> |操作|ROS 原生序列化|Protobuf|
|---|---|---|
|点云数据拷贝|**2 次完整深拷贝**|**支持浅拷贝**（仅传指针 + 长度）|
|内存碎片|大量maloc和new小块内存|自带Arena内存池，提前计算大小，一次性分配内存|
|消息体积|固定臃肿|有压缩机制，更小|


# ROS2零拷贝技术

ROS2 的 “零拷贝” 是一套分层、自动选择、按通信范围适配的技术组合，核心目标是完全避免或最小化数据内存拷贝。

整体上，ROS2 零拷贝包含 4 大核心技术点：
+ **进程内零拷贝（Intra-process Communication）**：直接传递 `unique_ptr` / `shared_ptr` 指针，不拷贝数据、不序列化；适用于同一进程内多个节点（Component 模式、多节点合并）。
+ **共享内存零拷贝（SHM / Data Sharing）**：FastDDS / CycloneDDS + iceoryx 共享内存池，适用于同一主机、跨进程通信。
+ **Loaned Messages**（借用消息 / 零拷贝池）：配合 SHM / Intra-process，彻底消除用户层拷贝。
+ **Type Adaptation / NITROS**（硬件加速零拷贝）：适用于CPU和GPU、FPGA、加速器等硬件之间的数据传输。


# 点云数据格式

```cpp
struct PointCloud2
{
  // 头部（时间、坐标系）
  std_msgs::msg::Header header;

  // 点云宽度、高度（有序=图像，无序=高度=1）
  uint32_t width;
  uint32_t height;

  // 每个点有哪些字段（x/y/z/rgb/intensity等）
  std::vector<PointField> fields;

  // 一个点占用多少字节
  uint32_t point_step;

  // 一行数据占用多少字节（width * point_step）
  uint32_t row_step;

  // 真正的点云二进制数据（一大段连续内存）
  std::vector<uint8_t> data;

  // 是否是稠密点云（无无效点）
  bool is_dense;
};
```

## data

一个简单的3D点云二进制数据，组织的方式为：
- 0~3 字节 → 存 x 坐标
- 4~7 字节 → 存 y 坐标
- 8~11 字节 → 存 z 坐标

```cpp
data = [x0][y0][z0][x1][y1][z1][x2][y2][z2]...
```

其实就是`vector<XYZ>`这种结构类型的内存分布。

当然直接用二进制数组表示的好处是类型无关，例如也能表示`vector<XYZRGB>`类型：
- **0~3 字节**：x 坐标（float32）
- **4~7 字节**：y 坐标（float32）
- **8~11 字节**：z 坐标（float32）
- **12~15 字节**：颜色（R+G+B+空字节）

```
data = [x0][y0][z0][rgb0][x1][y1][z1][rgb1]...
```

看着似乎跟C++模板相似，但是这里不同用模板来做实现，因为：
+ 但是由于ROS消息跨语言，java\python都要能解析；
+ 一个话题 `/points` 既能发 XYZ，也能发 XYZRGB；

## PointField

定义了一个点包含的属性。

```cpp
struct PointField
{
  std::string name;   // "x", "y", "z", "rgb", "intensity"
  uint32_t offset;    // 从点起点开始的字节偏移
  uint8_t datatype;  // 数据类型：FLOAT32=7, UINT8=2, FLOAT64=9
  uint32_t count;    // 一般是1
};
```

3D点云通常由3个field来描述，注意不是所有的点都要存额外3个field，而是整个PointCloud2只需要存3个field。（而且也不允许fields混杂的情况，即前半部分是XYZ、后半部分是XYZRGB）
```cpp
fields[0] = x, offset=0, type=FLOAT32
fields[1] = y, offset=4, type=FLOAT32
fields[2] = z, offset=8, type=FLOAT32
```

## width、height

如果是无序点云（height=1），width代表点云总数量。

一般来说，深度相机得到的点云像素会组织成有序点云，例如100\*100的图像，那么width等于100而不是压缩成一维的10000。有序点云可以像图像处理所以具体位置的像素点。

## point_step

一个点占多少字节

- 纯 XYZ：12
- XYZ+RGB：16
- XYZ+Intensity：16

## row_step

一行的字节数 = width × point_step，在无序点云中也代表总点云占用字节数。

## 适用传感器

对于单线激光雷达来说，一般更常用`sensor_msgs::LaserScan`类型，携带角度、距离信息。

而3D多线激光雷达、深度相机、3D模型基本都适用`sensor_msgs/PointCloud2`。




# 共享内存（SHM）

## 原理

当DDS参与者（Participant）检测到通信的另一个端点位于同一台主机时，它会优先尝试建立共享内存通道。数据会被写入一块预先分配好的共享内存区域，订阅者则直接通过内存指针访问这块区域，完全避免了数据在用户空间和内核空间之间的来回拷贝。关键机制如下：
+ **传输层自动选择**：Fast DDS内置了一个传输层选择器。当创建`DataWriter`和`DataReader`时，它会根据对端地址决定使用SHM（共享内存）还是UDPv4。这个过程对ROS2应用层是透明的。
+ **内存池管理**：为了避免频繁的动态内存分配，Fast DDS的SHM传输使用了一个内存池。你可以通过XML配置调整这个池子的块大小和数量，以适应不同消息尺寸的需求。
+ **回退机制**：如果共享内存通道因任何原因（如权限不足、内存耗尽）建立失败，Fast DDS会自动回退到标准的网络传输，确保通信不会中断。

## 适用场景

| 场景特征           | 是否推荐  | 理由                               |
| -------------- | ----- | -------------------------------- |
| 发布和订阅者位于同一物理机  | 强烈推荐  | 这是SHM发挥作用的先决条件，能获得最大性能收益。        |
| 消息频率 > 100 Hz  | 推荐    | 高频消息下，数据拷贝开销占比显著，优化效果明显。         |
| 消息体较大（> 64k）   | 推荐    | 当传输数据量大于64k时，零拷贝可以提供显著的性能提升。     |
| 跑大模型导致CPU吃紧    | 推荐    | 共享内存能把 memcpy 开销基本干掉，让 CPU 专心跑模型 |
| 对端在不同主机或容器     | 不适用   | SHM无法跨物理机工作，此时会回退到网络传输。          |
| 消息类型包含动态数组或字符串 | 谨慎使用  | 大小动态调整导致无法预分配，内存不连续。             |
| 系统内存非常紧张       | 评估后使用 | SHM需要预分配内存池，可能增加内存压力             |

> [!NOTE] SHM的缺点
> 共享内存传输虽然减少了CPU拷贝开销，但引入了一个新的潜在瓶颈——**内存访问竞争**。如果多个线程同时高频读写同一块共享内存，需要注意缓存一致性和锁竞争问题。在实际项目中，我们曾遇到过因订阅者处理速度慢导致共享内存池被填满，进而触发传输层回退的情况。监控/dev/shm目录的使用情况是个好习惯。

> [!NOTE] PCL格式 VS PLY格式
> |对比维度|PCD (Point Cloud Data)|PLY (Polygon File Format)|
|---|---|---|

|**工具支持**|PCL、ROS、CloudCompare|几乎所有 3D 软件（Blender、MeshLab、CloudCompare 等）|


### 发布者实现

创建ros2包，系统会自动生成`package.xml`、`CMakeLists.txt`。
```sh
ros2 pkg create --build-type ament_cmake pointcloud_test --dependencies rclcpp sensor_msgs pcl_ros pcl_conversions
```

点云数据发布流程如下：
+ 为了方便测试多个模型，采用参数服务器；
+ 加载 PCD 模型文件
+ 转为ROS2 `sensor_msgs::msg::PointCloud2`消息类型
+ 创建发布者并启用定时发布

```cpp
class PointcloudPublisherNode : public rclcpp::Node {
public:
    PointcloudPublisherNode(): rclcpp::Node("pointcloud_publisher") {
        // 读取发布频率, 默认10Hz
        publish_frequency_ = this->declare_parameter<int>("publish_frequency", 10);
        // 读取点云文件路径
        pcd_path_ = this->declare_parameter<std::string>("pcd_path");
        if (pcd_path_.empty()) {
            RCLCPP_ERROR(this->get_logger(), "pcd_path is not set");
            return;
        }
        // 1. 加载 PCD 模型
        pcl::PointCloud<pcl::PointXYZ> cloud;
        if (pcl::io::loadPCDFile(pcd_path_, cloud) != 0) {
            RCLCPP_ERROR(this->get_logger(), "Failed to load pcd file");
            return;
        }
        RCLCPP_INFO(this->get_logger(), "加载 Lucy 点云成功：%zu 个点，大小约 %.1f MB", 
        cloud.size(), cloud.size() * 12.0 / 1024.0 / 1024.0);
        // 2. 转换为 ROS2 消息
        pcl::toROSMsg(cloud, cloud_msg_);
        cloud_msg_.header.frame_id = "map";
        // 3. 创建发布者（QoS 设置为 SensorData，适合点云）
        publisher_ = this->create_publisher<sensor_msgs::msg::PointCloud2>("pointcloud", rclcpp::SensorDataQoS());
        // 4. 创建定时器，按照指定频率发布点云
        timer_ = this->create_wall_timer(std::chrono::duration<double>(1.0 / publish_frequency_), [this]() {
            // 记录发送时间戳, 以计算传输耗时
            cloud_msg_.header.stamp = this->now();
            publisher_->publish(cloud_msg_);
        });
    }
private:
    rclcpp::Publisher<sensor_msgs::msg::PointCloud2>::SharedPtr publisher_;
    rclcpp::TimerBase::SharedPtr timer_;
    sensor_msgs::msg::PointCloud2 cloud_msg_;
    int publish_frequency_;
    std::string pcd_path_;
};
```

### 订阅者实现

订阅者的逻辑主要是基于消息时间戳差来做延迟统计。

```cpp
class PointCloudSubscriber : public rclcpp::Node {
public:
    PointCloudSubscriber() : Node("pointcloud_subscriber"), count_(0), total_latency_(0.0) {
        // 1. 创建订阅者（QoS 与发布者一致）
        sub_ = this->create_subscription<sensor_msgs::msg::PointCloud2>(
            "pointcloud",
            rclcpp::SensorDataQoS(),
            [this](const sensor_msgs::msg::PointCloud2::SharedPtr msg) {
                callback(msg);
            }
        );

        // 2. 定期打印统计信息（每 5 秒）
        stats_timer_ = this->create_wall_timer(std::chrono::seconds(5), [this]() { print_stats(); });
    }

private:
    void callback(const sensor_msgs::msg::PointCloud2::SharedPtr msg) {
        // 1. 计算端到端延迟：当前时间 - 发布时间
        rclcpp::Time now = this->now();
        rclcpp::Time publish_time = msg->header.stamp;
        double latency_ms = (now - publish_time).seconds() * 1000.0;

        // 2. 累加统计
        count_++;
        total_latency_ += latency_ms;
        latencies_.push_back(latency_ms);

        RCLCPP_DEBUG(this->get_logger(), "收到点云，延迟：%.2f ms", latency_ms);
    }

    void print_stats() {
        if (count_ == 0) {
            RCLCPP_WARN(this->get_logger(), "尚未收到任何点云数据");
            return;
        }

        // 计算平均延迟和最大延迟
        double avg_latency = total_latency_ / count_;
        double max_latency = *std::max_element(latencies_.begin(), latencies_.end());

        RCLCPP_INFO(this->get_logger(), "=== 性能统计 ===");
        RCLCPP_INFO(this->get_logger(), "接收消息数：%zu", count_);
        RCLCPP_INFO(this->get_logger(), "平均延迟：%.2f ms", avg_latency);
        RCLCPP_INFO(this->get_logger(), "最大延迟：%.2f ms", max_latency);
        RCLCPP_INFO(this->get_logger(), "=================");

        // 重置统计（可选，用于分段统计）
        // count_ = 0;
        // total_latency_ = 0.0;
        // latencies_.clear();
    }

    rclcpp::Subscription<sensor_msgs::msg::PointCloud2>::SharedPtr sub_;
    rclcpp::TimerBase::SharedPtr stats_timer_;
    size_t count_;
    double total_latency_;
    std::vector<double> latencies_;
};
```


### 共享内存开关

前面提到ROS2的共享内存机制是传输层自动选择的，即只要在同一物理机上，进程间通信就会有限选择共享内存。

为了对比测试，便携xml传输配置来控制只使用UDP和只使用SHM。

新建`pointcloud_test/config/shm_only.xml`
```xml
<?xml version="1.0" encoding="UTF-8" ?>
<profiles xmlns="http://www.eprosima.com/XMLSchemas/fastRTPS_Profiles">
    <transport_descriptors>
        <!-- 定义共享内存传输 -->
        <transport_descriptor>
            <transport_id>shm_transport</transport_id>
            <type>SHM</type>
            <!-- 共享内存段大小（根据点云大小调整，这里设为 400MB） -->
            <segment_size>419430400</segment_size>
        </transport_descriptor>
    </transport_descriptors>

    <participant profile_name="shm_participant" is_default_profile="true">
        <rtps>
            <!-- 使用共享内存传输 -->
            <userTransports>
                <transport_id>shm_transport</transport_id>
            </userTransports>
            <!-- 禁用内置传输（UDP/TCP） -->
            <useBuiltinTransports>false</useBuiltinTransports>
        </rtps>
    </participant>
</profiles>
```
新建`pointcloud_test/config/udp_only.xml`
```xml
<?xml version="1.0" encoding="UTF-8" ?>
<profiles xmlns="http://www.eprosima.com/XMLSchemas/fastRTPS_Profiles">
    <transport_descriptors>
        <transport_descriptor>
            <transport_id>udp_transport</transport_id>
            <type>UDPv4</type>
        </transport_descriptor>
    </transport_descriptors>

    <participant profile_name="udp_participant" is_default_profile="true">
        <rtps>
            <userTransports>
                <transport_id>udp_transport</transport_id>
            </userTransports>
            <useBuiltinTransports>false</useBuiltinTransports>
        </rtps>
    </participant>
</profiles>
```

然后在终端运行发布者、订阅者节点前都指定一下`FASTRTPS_DEFAULT_PROFILES_FILE`即可生效。
```sh
export FASTRTPS_DEFAULT_PROFILES_FILE=/home/lxq/robo-maria/src/ros2_learning_test/pointcloud_test/config/shm_only.xml

export FASTRTPS_DEFAULT_PROFILES_FILE=/home/lxq/robo-maria/src/ros2_learning_test/pointcloud_test/config/udp_only.xml
```

还需要再指定中间件：

```sh
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export RMW_FASTRTPS_USE_QOS_FROM_XML=1
```

## 实现

还是copy上面的`PointcloudPublisherNode`、`PointCloudSubscriber`放到一个`pointcloud_intra_process.cpp`里，形式如下：

```cpp
class PointcloudPublisherNode : public rclcpp::Node {

public:

PointcloudPublisherNode(): rclcpp::Node("pointcloud_publisher", rclcpp::NodeOptions().use_intra_process_comms(true)) {
	/* ... */
	timer_ = this->create_wall_timer(std::chrono::duration<double>(1.0 / publish_frequency_), [this]() {
		auto ptr = std::make_unique<sensor_msgs::msg::PointCloud2>(cloud_msg_);
		// 打印ptr的地址
		RCLCPP_DEBUG(this->get_logger(), "发布点云，地址：%p", static_cast<const void *>(ptr.get()));
		// 记录发送时间戳, 以计算传输耗时
		ptr->header.stamp = this->now();
		publisher_->publish(std::move(ptr));
	});
}

class PointCloudSubscriber : public rclcpp::Node {
public:
    PointCloudSubscriber() : Node("pointcloud_subscriber", rclcpp::NodeOptions().use_intra_process_comms(true)), count_(0), total_latency_(0.0) {/*...*/}
    
private:
	void callback(const sensor_msgs::msg::PointCloud2::UniquePtr& msg) {
		/* .. */

        RCLCPP_DEBUG(this->get_logger(), "收到点云，地址：%p, 延迟：%.2f ms", static_cast<const void *>(msg.get()), latency_ms);
    }

int main(int argc, char ** argv) {
    rclcpp::init(argc, argv);
    rclcpp::executors::SingleThreadedExecutor executor;
    auto publisher_node = std::make_shared<PointcloudPublisherNode>();
    auto sub_node = std::make_shared<PointCloudSubscriber>();
    executor.add_node(publisher_node);
    executor.add_node(sub_node);
    executor.spin();
    rclcpp::shutdown();
    return 0;
}
```

需要注意几个点，要保证使用move移动语义来实现零拷贝，传给`publish`的必须是`UniquePtr`，而不能是`cloud_msg_`，否则还会产生拷贝。其次因为移动之后，`ptr`的资源会被置空，因此不能直接将成员变量直接定义为`UniquePtr`，而定义`SharePtr`的话，似乎`publish`没有这样的构造。

总之，最后就是在回调中先构造一个`UniquePtr`，然后在构造完后再填充stamp，否则将这次构造的时间统计进去的话会有10ms多的延迟。这里我们只算传输延迟。

其次，在`main`函数中，不能通过下面这种方式来`add_node`，因为`executor`不持有或者仅持有node的`week_ptr`，这样在`add_node`执行完后，`std::make_shared<PointcloudPublisherNode>()`右值就会析构掉。
```cpp
rclcpp::executors::SingleThreadedExecutor executor;
executor.add_node(std::make_shared<PointcloudPublisherNode>());
executor.add_node(std::make_shared<PointCloudSubscriber>());
executor.spin();
```

这个原理类似于下面的实现。

```cpp
class A {
public:
    A() {
        cout << "A " << endl;
    }
    ~A() {
        cout << "~A" << endl;
    }
    void test() {
        cout << "test" << endl;
    }
};

void func(std::shared_ptr<A> obj) {
    obj->test();
}

int main()

    func(std::make_shared<A>());
    cout << "after func" << endl;
}
```
