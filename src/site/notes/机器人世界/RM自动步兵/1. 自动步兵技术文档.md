# 定位

机器人的全场定位功能是所有其他功能的基础。我们使用了成熟的AMCL算法基于以下原因：

+ 基于重要性粒子重采样的方法间接地表达了概率，使得利用融合多信息（如激光雷达、UWB）进行定位成为可能。
+ 长期权重和短期权重的设计一定程度上解决了比赛过程中可能出现的“机器人绑架问题”。
+ 粒子集合的大小是影响粒子滤波器计算效率的重要因素。KLD算法能够自适应的调整粒子数量上界，在确保定位准度的情况下减轻了计算负担。
+ 作为一个经典的算法，ROS有相应的功能包可供移植。

# 建图

建图的目的在于获得静态地图。我们目前使用的是Gmapping框架，由于它并没有真正意义上的回环检测过程，所以在建图效率和精度上表现一般，我们计划等其他模块开发基本完毕会考虑效果更好的Cartographer等其他算法。

在建图过程中，我们发现车体对雷达的部分遮挡会导致严重的定位和建图失败，因此我们在官方的rplidar包基础上加入了角度滤波。

其次，因为激光数据的获取存在周期、在测量时又伴随机器人的运动，所以存在点云的畸变，所以我们将每帧的激光点坐标变换到相应时刻的机器人里程计上，来去除畸变带来的影响。

# 全局规划

全局规划层的作用是根据地图信息进行路径规划，我们采用了JPS算法，系统地实现了Tie Break，在较复杂的比赛场地下，相比于A\*算法减少了OpenList中的节点，提高了规划的效率。

局部规划层主要是使机器人具备动态避障的能力，对此我们选择了TEB融合导航算法作为局部规划器。

# 仿真调试

## Stage+rviz平台

Stage是基于2D平面的多机器人仿真平台，使用.world文件配置模拟环境，可以加载静态地图，仿真激光雷达、相机、里程计和简单的机器人模型。我们主要利用Stage+rviz平台进行简单环境下的导航算法验证和调试。
