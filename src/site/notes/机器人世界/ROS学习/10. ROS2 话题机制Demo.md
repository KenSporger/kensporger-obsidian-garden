# 主要差异

|               | ROS1                                                                                                                       | ROS2                                                                                                                                                                                 |
| ------------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 构建工具          | `catkin_make`、`catkin build`                                                                                               | `colcon build`                                                                                                                                                                       |
| `package.xml` | 1. buildtool_depend: catkin<br>2. depend：roscpp<br>3. 消息build：message_generation<br>4.exec_depend：message_runtime <br><br> | 1. buildtool_depend：ament_cmake<br>2. depend：rclcpp<br>3. 消息build：rosidl_default_generators<br>4. exec_depend：rosidl_default_runtime<br>5. member_of_group：rosidl_interface_packages |
| `CMakeLists`  | `find_package(catkin ...)`、`catkin_package()`、`generate_messages()`                                                        | `find_package(ament_cmake REQUIRED)`、`ament_package()`、`rosidl_generate_interfaces()`                                                                                                |

# 自定义消息类型

对于内置、还是自定义的消息类型，在命名空间上都增加了一层msg：
```cpp
// ROS1
#include<geometry_msgs/Twist.h>
geometry_msgs::Twist
learning_topic::Person

// ROS2
#include <geometry_msgs/msg/twist.hpp>
geometry_msgs::msg::Twist
learning_topic::msg::Person
```

`Person.msg`基本沿用，但ROS2 的枚举常量名必须是**全大写**。
```cpp
string name
uint8 age
uint8 sex

uint8 UNKNOWN = 0
uint8 MALE = 1
uint8 FEMALE = 2
```

编译生成的代码和[[机器人世界/ROS学习/04. ROS1 话题机制Demo#^ea2e3c\|04. ROS1 话题机制Demo#^ea2e3c]]类似，定义在`./install/learning_topic/include/learning_topic/learning_topic/msg/detail`路径下。


# 发布者

```cpp

// 节点做了封装, 把Publisher作为了成员变量, 循环发布消息逻辑放在构造函数中
// 类封装的好处是避免变量的污染
class PersonPublisherNode final : public rclcpp::Node
{
public:
  PersonPublisherNode()
  // ROS1 发布节点名字直接在init中传入
  : rclcpp::Node("person_publisher")
  {
    // 不再像ROS1一样要先创建NodeHandle
    /* 
    ros::NodeHandle n;
	  ros::Publisher person_info_pub = n.advertise<learning_topic::Person>("/person_info", 10);
    */
    publisher_ = this->create_publisher<learning_topic::msg::Person>("/person_info", 10);
    // ROS2是创建了一个定时器，通过回调来发布, ROS1则是通过loop_rate.sleep()+while的方式
    timer_ = this->create_wall_timer(1s, [this]() {
      learning_topic::msg::Person msg;
      msg.name = "Tom";
      msg.age = 10;
      msg.sex = learning_topic::msg::Person::MALE;

      publisher_->publish(msg);
      RCLCPP_INFO(
        get_logger(),
        "Publish Person Info name:%s age:%u sex:%u",
        msg.name.c_str(),
        msg.age,
        msg.sex);
    });
  }

private:
  rclcpp::Publisher<learning_topic::msg::Person>::SharedPtr publisher_;
  rclcpp::TimerBase::SharedPtr timer_;
};

int main(int argc, char ** argv)
{
  // ros::init(argc, argv, "person_publisher"); // ROS1节点名字直接在init中传入
  rclcpp::init(argc, argv);
  // ROS1 发布节点没有spin、shutdown，现在都统一了
  rclcpp::spin(std::make_shared<PersonPublisherNode>());
  rclcpp::shutdown();

  /* 订阅节点的结构也和发布节点一样
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<PersonSubscriberNode>());
  rclcpp::shutdown();
  */
  return 0;
}

```


# 订阅者

订阅节点写法和ROS1倒是差别不大，通过塞入回调来处理。

```cpp
subscription_ = create_subscription<learning_topic::msg::Person>(
  "/person_info",
  10,
  [this](const learning_topic::msg::Person & msg) {
	RCLCPP_INFO(
	  get_logger(),
	  "Subscribe Person Info: name:%s age:%u sex:%u",
	  msg.name.c_str(),
	  msg.age,
	  msg.sex);
  });
```


# 回调的生命周期问题

发布、订阅的回调函数没有像CSDK一样做wp保护，是否合理？

- `timer_` 是 `Node` 的成员（`rclcpp::TimerBase::SharedPtr timer_;`），只要 `Node` 活着，timer 就活着；`Node` 析构时，成员先析构，timer 会被销毁/取消。
- 回调的执行依赖 `spin()` 的执行器。你在 `main()` 里是 `rclcpp::spin(std::make_shared<PersonPublisherNode>())`，`spin()` 持有这个 `shared_ptr`，因此在 `spin()` 返回前节点不会被销毁。
但如果以后把节点用在更复杂的管理方式里（比如：把 timer 交给其他对象、或把 callback 存到别处、或 node 不再由 `spin(shared_ptr)` 直接持有），那 `lambda [this]` 这种写法可能变危险。
